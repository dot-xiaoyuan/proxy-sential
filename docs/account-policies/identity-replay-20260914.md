# 身份归责回放修正（2026-09-14）

本步完成账号策略消费侧会话回放修正，不代表身份对账和账号详情整阶段完成。

## 实现

- 将标准身份事件的 session_status 保留在策略身份事实中。无需数据库表结构变更，新增字段存入现有 JSONB；旧事实没有该字段时保持保守行为。
- 按事件时间重放事实；相同时间使用确定性排序，下线优先结束区间。
- 同一来源、园区、接入域、会话 ID、IP 下，已结束会话后的明确 start/login/accounting-start 开始独立有效区间；普通心跳不能重新激活已下线会话。
- 重复确认时间去重，迟到下线按发生时间应用。稀疏心跳继承已有设备、用户组、产品、VLAN 和确认周期。
- 未结束区间内出现不同账号归属仍标记冲突，不自动确认归责。
- 三个心跳周期的有效区间采用左闭右开边界；到期立即未知，无确认历史的兼容数据与完整确认历史一致。

## 验证

- `go test ./internal/policy ./internal/store ./internal/controlplane ./internal/adapter/identity` 通过。
- 本地 PostgreSQL：`go test -race ./internal/store -run 'TestPostgresPolicyIdentityReplayMatchesFileFold|TestPolicySession' -count=1` 通过。
- 回放覆盖重复、乱序、迟到下线、相同会话 ID 重新登录、稀疏心跳、已下线后的心跳、同时账号冲突及过期边界。
- 数据库测试在三个查询时刻比较 PostgreSQL 事实读回与文件模式共用折叠函数结果；此项不是完整认证源现场验证。
- 未修改前端，未操作生产环境。
