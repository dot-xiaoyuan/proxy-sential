# 全接口优化实施与验收记录（进行中）

尚未完成全接口验收，尚未部署到 192.168.0.30。以下是隔离环境阶段性结果，不能作为全部接口已达标的结论。现场业务数据未清洗、未备份，现场迁移尚未执行。

## 隔离环境与有效业务数据

- 自有 PostgreSQL / ClickHouse 容器，独立 `sentinel_benchmark` 数据库；写压测需验证专用服务的隔离声明，禁止仅凭 localhost 判断可写。
- 1,000 万基础应用观测、1,000 万标准事件；24,002 份案件证据快照、24,000 个终端、170 万条证据及配置、案件、动作和策略夹具。
- 品牌和系统字段由明确的原始识别属性生成，包含 macOS，保留 MAC 厂商参考与品牌的区分。此前错误传感器导致的空统计不用于验收。
- 持续负载：每秒 100 条标准事件及应用观测、10 条重分类；每五秒提交实际风险导出任务。采用独立持久化任务文件目录，支持随后进行重启验证。

## 已实现的主要路径

- 校区、楼栋、网络区域及接入点按记录同步提交，提交后立即可见；案件详情及历史、单案件写入、策略定义写入、连接器配置与处置回调使用目标记录事务。
- 读请求不使用旧运营文档的全局写锁；旧文档保存跳过未修改记录。案件、连接器和动作的版本检查拒绝陈旧后台保存，防止覆盖新配置、密钥或回调结果。
- 案件历史增加分页接口；终端分页使用批量身份历史读取，IP 过滤在数据库分页前执行，补齐排序与关联索引。
- 应用最新版本、连接累计计量及五分钟事实表；应用观测分类汇总会撤掉重分类前的旧计数，窗口边界读取精确的规范事件。
- 活动图表采用规范事件字段与五分钟增量统计，保留 DNS/HTTP/TLS、JA3/JA4 等原有维度和任意时间边界。
- 统计缓存按用户、权限及查询隔离，合并相同请求，来源时间最多五秒；识别统计提前刷新，准备成功后才通过就绪检查。刷新失败及过期来源返回错误。
- 导出及规则包、连接器探测采用持久化任务、有界 worker、状态查询和取消；页面展示任务进度、统计时间及案件历史分页。
- ClickHouse JSON 日期统一带时区，避免 UTC 汇总与旧上海时区列产生八小时偏差；后台游标保留纳秒精度。
