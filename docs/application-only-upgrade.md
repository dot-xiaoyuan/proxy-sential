# 已安装现场的应用版本更新

`upgrade-application.sh` 用于已有完整数据库与配置的现场，仅切换已验证的应用发布包。它不会创建、执行或跳过数据库迁移。候选包中的全部 PostgreSQL、ClickHouse 迁移，必须已在现场迁移账本中执行且校验值完全一致；缺失或修改迁移时立即拒绝。需要数据库升级时使用完整安装器；184 测试联调环境按当前约定传 `--skip-backup`，不执行例行数据库备份。

发布前在独立隔离的测试库回放候选版本，完成相关 Go 与前端验收；没有独立测试库时如实记录真实 SQL 集成验证缺口。修复和现场预检完成后只构建一个 Linux amd64 包，本地与现场只保留 `proxy-sentinel-current.tar.gz` 及其校验文件；内部不可变 `VERSION` 使用日期与源码提交短哈希，不使用 `rNN` 轮次。发布清单记录 Git 版本和工作区是否含未提交改动，包外和包内均有 SHA256 校验。

```bash
scripts/deploy/build-release.sh --version VERSION --output dist/proxy-sentinel-current.tar.gz
```

将发布包、`.sha256`、`upgrade-application.sh`、`verify-applied-migrations.py`、`verify-application-cli.py`、`verify-application-runtime.py`、`validate-release-archive.py` 与 `manage-frontend-previous.py` 放入现场同一暂存目录，执行：

```bash
bash upgrade-application.sh --version VERSION \
  --archive proxy-sentinel-current.tar.gz \
  --checksum proxy-sentinel-current.tar.gz.sha256
```

发现采集进程的内存队列已积压、且服务设置为 `Restart=on-failure` 时，可在上述命令末尾加 `--defer-discovery-restart`。脚本先核对旧进程、验证候选包并切换发布目录，重启其他活动服务；发现进程继续运行并写完队列，待其自行退出并由 systemd 启动候选版本后，脚本才做完整验收并更新 `previous`。等待上限为 45 分钟；若新发现进程已启动但验收失败，脚本报告未完成状态并保留候选进程及原发布目录，避免自动回退时中断新的内存队列。此时是**尚未完成的临时混版切换**，必须跟踪至采集进程也运行候选版本，不能只切指针后结束任务。

仅更新读取端或其他消费者、无需替换发现采集实现时，可用 `--preserve-discovery` 暂留正在运行的发现进程。它与延迟重启选项互斥；脚本仍检查旧进程属于 current/previous、候选参数兼容以及服务存活，但不主动重启，也不等待它自然退出。该选项只能用于受控切换窗口；验收单版本前必须跟踪发现进程自然退出或完成重启，并核对实际执行文件，不能把混版留作常态。

同一不可变候选目录已由前次中止的切换留下时，可加 `--resume-existing` 继续原包。脚本重新检查归档 SHA256、发布清单及候选目录逐文件哈希，目录内容必须与原包一致；该选项不允许覆盖已存在的发布目录，也不跳过迁移、参数或运行版本核对。

切换前后均核对所有活动进程的实际执行文件，尤其是脚本未自动重启的 NCU 派生、DHCP 逐消息、EVE ingest、分钟影子和识别物化器。它们不因 `current` 指针切换而自动变为新版本；验收时所有活动应用进程与有效 systemd 启动路径必须指向同一个候选发布目录。包外发布工具如确需使用，记录其源码提交和 SHA256，并在同一任务内收敛到统一版本。

更新脚本持有安装锁，验证包成员路径、逐文件校验、平台和版本，以及两套数据库的已应用迁移。确认通过后保留原发布目录，原子切换 `current`，重启当前启用的常驻应用服务，再检查所有服务和 `/readyz`。失败时切回原目录并重启应用；成功时原版本记入 `previous`。业务数据库不参与切换，也不需要在空间不足的根盘复制一份完整数据库。

184 测试环境按单版本约定，在验收且核对活动进程、有效 systemd 路径和挂载后，于同一任务内清理无引用的旧程序目录、包和暂存，移除 `previous` 与 `frontend-previous`。无需为每个旧程序目录另做备份或恢复归档；记录版本与清理数量即可。清理后不再有现场即时应用回退版本；下一次更新仍在切换和验收期间暂留前版。配置、数据库、原始证据和案件数据不参与程序版本清理。

该流程沿用已有 systemd 单元与现场配置。需要更改采集器启动、可信来源登记或运行参数时，另存一份对应配置与单元备份，并单独验证重启后的采集。不要把未验证的新配置当成程序回退即可自动恢复的内容。

指纹库激活与历史回填分开。默认不在控制面重启、导入指纹库或识别规则变化时启动历史重算；识别历史 lane 也不领取旧任务。只有显式配置 `PROXY_SENTINEL_FINGERPRINT_HISTORY_BACKFILL=true` 才启用这些入口。关闭时保留旧任务、失败状态和处理计数，实时识别继续处理新输入，不把未处理历史标为完成。现场已有完整指纹库时，应保留其 OUI、Fingerbank 和其他来源，仅更新本次规则及可核验清单；应用包内的 bootstrap 不应覆盖已有完整来源。

切换和验收期间需要回退时，确认 `previous` 对应受测版本，并检查附加配置的兼容性。`proxy-sentinelctl rollback` 会切换链接并重启启用的控制面、入库、风险、设备、读模型、识别和发现服务。数据库迁移不会反向执行。验收并清理旧包后，需从 Git 和发布构建流程重新生成候选包，不依赖长期保留的现场旧版本。

设备信号 `--device-signal-stream4-keys` 须分两次独立发布。先发布 PG248、精确/批量收据、历史、案件证据的兼容读者，保持写入开关关闭，验证旧 `stream-` journal 和真实页面；再发布一个同样具备兼容读者的不可变版本，使第一次发布成为 `previous`，核对两个版本的源码、迁移账本及可执行文件后才开启开关。只关闭开关并排空新段属于写入回退；stream4 键还可能被当前态、变化与案件引用，不支持 stream4 的旧程序不能作为应用回退。灰度失败时先停止抓包接收，让兼容版本完成已入 journal 的各落点，再恢复上一兼容版本；保留原始文件、来源 epoch、游标和未完成缺口。写入版通过真实持续输入与页面验收后按单版本约定清理旧发布。

应用切换前还会读取活动服务的启动参数，只提取参数名，与候选程序的帮助输出核对。缺少现场正在使用的参数时，在切换 `current` 前拒绝发布；这不能代替相关协议和数据库回放测试。

### 184 共享来源修复与验证

包含 `254_shared_stream_continuity.sql` 的候选包走完整安装迁移流程。预检同时读取文件切换与共享切换账本，核对两个 sidecar 的路径、作用域及启动参数。运行中的新报文代际若还没有共享绑定，先保持两个采集器持续写源文件，暂停共享判定与 packet 文件消费以取得该文件的独占租约。握手文件消费者保留现有游标。

对已切换文件的单来源修复，运行 `ingest stream-shared-activate`，提供 `--replace-packet-binding`、`--packet-source`、`--packet-epoch`、`--packet-journal-dir`、`--packet-old-audit`、`--packet-old-audit-sha256` 及正常的 sensor、采集作用域和接口参数。审计文件与校验值从现场证据取得。命令核对已落盘游标并事务切换共享绑定。重复调用须使用完全一致的参数。后续需要同时更换文件与共享绑定时，向 `stream-prepare` 提供 `--replace-closed-epoch`、`--replace-shared-old-audit` 和 `--replace-shared-old-audit-sha256`，并使用新 journal 目录。命令先持久化新游标再事务切换账本。

绑定吻合后，在两个文件消费者及控制面设置 `PROXY_SENTINEL_STREAM_SHARED_REQUIRED=true`，在握手采集器设置 `PROXY_SENTINEL_HANDSHAKE_CAPTURE_V2=true`。核对生效环境和进程后恢复消费与仅记录判定。`ingest stream-shared-repair` 接收 `--packet-source`、`--packet-epoch` 与采集作用域参数，每次最多处理 16 条归档定位，返回 `complete` 或 `paused_for_realtime`。在实时处理运行期间逐页执行，遇到实时积压暂停领取。过期项保留独立的事件级审计，原始接纳时间和内容哈希来自原归档。补账写入成本为每个核验事件一条窄记录，每个来源代际一条检查点。日常读取从小型运行进度表及共享收据索引取数。运行报告只保存每来源代际的最新样本。

验收读取授权的 `/api/v1/shared-access/status`，核对 `materialization.source_progress` 的绑定、最近接纳、归档、共享确认、待办段和失败位置。最近处理位置可能越过独立车道的慢段，仍需核对最老待办和失败状态。恢复 ClickHouse 合并时逐表启用，观察部件、水位与磁盘余量，再恢复 `account_sessions` 的自动清理。用真实输入覆盖维护运行期间的净积压斜率，并核对一条符合条件的真实共享样本及其仅记录处置和上报。

需要回退时，先暂停补账和共享判定，将两个环境开关恢复到发布前状态。保留现行文件游标和已应用迁移，先验证上一兼容版本能处理现有段和覆盖字段，再执行应用回退。保留绑定审计和未完成水位，已有路由及案件证据仍按原引用读取。获得现场闭环与正常维护下的容量验收后按单版本约定清理旧程序。
