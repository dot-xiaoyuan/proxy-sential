# 风险处置列表加载修复（2026-09-15）

## 原因与修复

数据库模式的 `GET /cases` 原先在返回列表前同步执行七天代理证据汇总和案件更新；随后通过 operations 全局互斥锁读取列表，隐式开启事务、等待处置全局数据库锁，并重载案件证据历史、动作和配置。因此一次列表访问会等待与分页无关的处理，且与后台处置争用同一锁。

数据库模式现改为直接读取 `risk_cases`，在数据库过滤、排序和分页；不触发风险汇总，不读取证据历史，不获取 operations 互斥锁或其事务锁。使用五秒请求期限和只读一致性事务返回总数及当前页。排序增加稳定 case_id 次序，响应保留原分页格式。新增 023 索引支持队列排序。

案件生成和更新继续交由已有后台同步任务（每三十秒触发）；刷新列表只读取已生成案件。文件回放模式保留原有行为。本次不改页面布局，也不改处置动作的执行语义。

2026-10-01 补齐后台十分钟滚动窗口与数据库复核存储的契约；公众复核列表仍使用 24 小时或 7 天。同步收到明确的可疑或正常评估后，更新未结案件的当前分数、置信度和评估等级，保留最初证据、追加评估历史，不自动关闭调查，也不改变人工负责人或优先级。采样没有包含某个 IP 不表示它已恢复正常，不能据此修改案件。

身份解析的“已调用”和“找到会话”分别处理。没有有效会话、会话冲突、证据归属与会话不一致或窗口要求补充身份证据时，清空当前案件中的账号、终端、认证会话及其组织/接入字段，并保留原因阻止处置；不以最后一条流量的会话替代整个混合归属窗口。后台同步错误单独参与健康检查，其他成功事务不会消除该错误。

对早期版本已经形成的同 IP 多个未结案件，按稳定顺序更新所有匹配案件的当前评估，不随机只更新其中一个。各案件保留原始去重键，避免改成同一个新键后触发未结案件唯一索引、导致整个同步事务回滚；案件编号、原始证据、负责人及人工调查状态均保留。

## 验证

- 新增回归用例，旧代码因列表触发证据聚合而失败，修复后通过。
- 本地真实 PostgreSQL 插入一万条隔离测试案件，同时持有 operations 互斥锁、全局 advisory lock 和证据历史表排他锁，列表仍正常返回。
- 首页二十条约 196 ms；下一页约 177 ms；组合筛选约 107 ms；越界空页约 179 ms（含 race、本地测试环境，不代表生产延迟）。
- 验证总数、分页游标、筛选、IP 格式及无证据历史载荷；测试数据按独立园区清理。
- 测试日志见 `artifacts/case-queue/`。

未操作生产服务。代码更新部署后才会影响正在运行的系统；尚无现场请求耗时记录。

最终验证：`go test ./...`、`go test -race ./internal/controlplane` 及上述 PostgreSQL 锁竞争集成回放全部通过。
