更新：2026-09-10。协调任务：调查 SNI 和 HTTP Host 设备识别；特征库任务：整改 Proxy Sentinel 域名管理。

## 最终验收目标

在标准事件上识别明确代理/隧道与共享上网风险，关联事件发生时的账号/终端身份，输出可解释的证据、窗口、评分、置信度及冲突原因；支持人工复核、影子策略、冷却、审计和撤销，并通过正常办公等负例验证。应用访问或推测品牌不能单独证明代理或多设备共享。

“规则能下载”“应用列表有数据”“风险有分数”分别只是中间结果，不能代替最终验收。真实处罚须满足现有处置准入条件；未满足时保持影子执行，并明确报告未完成项。

## 分工与协作

- 当前 Sentinel 任务统筹计划、跨仓契约、Sentinel 开发、联调和发布。
- featurelib-new 现有任务负责特征治理、发布索引、规则用途和可追溯来源，仅修改本仓库。分阶段交付后由统筹任务验证；不并行修改线上实例。
- 保留两个仓库已有未提交改动。每阶段保存测试结果、发布包、当前版本及恢复点。独立代理/任务的历史结论须用当前代码或现场数据核实。

### 第二阶段交付核对

featurelib 提交 `3600119` 已交付 `docs/anti-proxy/CAPABILITY_INVENTORY.md` 与11组 `standard-event-replay-v1.json` 合成正反向量。统筹已阅读并核对 Sentinel 的 `internal/normalized/event.go`：事件外壳兼容，但新增嵌套协议字段与证据类别尚非 Sentinel 已实现的判定契约。特征库侧向量校验通过不等同于 Sentinel 风险引擎回放通过。后续须先建立消费侧预期测试，并补齐不完整握手、请求响应连接冲突、失败响应和未知规则来源的反例；强协议证据也不能绕过授权与身份归责要求。

能力盘点确认 featurelib 当前不包含 CONNECT/SOCKS/VPN 协议解析器。协议解析继续由采集适配层转换为标准事件，特征库负责可追溯规则与用途元数据，风险层不得直接消费原始协议字段。

索引微基准：10个包、每包571条规则/313应用约44–47ms，分配约45MB。此为本地合成基准；当前重复解压可以后续优化，不代表线上测量。
