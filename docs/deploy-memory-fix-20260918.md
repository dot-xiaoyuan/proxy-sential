# 30 部署回填内存超限修复

现场 ClickHouse 为 25.9.2.1。版本迁移已执行至 016，应用最新观测、规范事件及活动历史键回填已登记完成，失败出现在随后活动读模型追平阶段；正式二进制尚未因此次失败而切换。

修复活动和应用观测小时/天汇总：每次查询只重建一个时间桶及网络范围；不可变主键前缀在 FINAL 前筛选，正计数条件仍在 FINAL 后判断，避免旧版本计数复活。查询内存上限维持 256MiB，分组溢写阈值为 64MiB；显式限制 INSERT 缓冲为 8MiB、块大小为 2048，同样限制其他流式回填的插入缓冲。错误补充回填阶段、目标表及桶信息。

活动通知每次读取最多 1000 条连续记录，仅处理包含最多 20 个不同时间桶/网络范围的连续前缀，合并其中的重复通知；游标只推进到该前缀末尾，不能跨过未处理范围。新增回放覆盖交错重复通知和跨网络范围截断。

失败不会提交 PostgreSQL 游标。新增回放让两个日期中第二个日期汇总失败：验证游标不变，重试后的计数既不丢失也不重复。规范活动及应用计量回放、相关后端测试通过。

30 上对应小时到天汇总及旧值/新值 UNION 的只读查询在相同 256MiB 限制下通过。临时 Linux 程序已完成整条迁移与追平流程，退出码 0；ClickHouse 当前版本 016，PostgreSQL 当前版本 042，四项历史回填登记均为 completed。活动游标已越过原失败位置，应用观测游标追至 2026-09-18 02:39:29 UTC。未替换正式程序、未重启服务，不备份、不清洗业务数据。最终程序包含流式 INSERT 缓冲限制及连续通知合并。
