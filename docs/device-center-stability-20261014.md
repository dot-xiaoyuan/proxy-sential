P95/P99 均未达标，单轮下降不足以确认效果。以上不是终端和网络设备接口的并发验收，更不是 10 倍容量验收。浏览器的四标签访问与该负载测试分别记录。

哑终端首屏 `EXPLAIN (ANALYZE,BUFFERS)` 只读采样：使用状态部分索引和服务事实主键索引，状态命中 37 行、返回 21 行，SQL 执行 3.123 ms、计划 3.834 ms；顶层 176 个缓存命中块、57 个读取块。它证明这一条小结果集查询的形态，不代表整个接口、其他筛选或全量数据都快。

10 条真实事件均通过设备历史 API 找到对应 event_id。其中 5 条账本 accepted_at 到 applied_at 超过 5 秒，最大约 2562 秒。测量保存了事件、修订、接受、处理、探针观测时间及 HTTP 结果，没有保存口令。

**计时缺口**：发现路径在写入持久任务时设置 started_at，处理后又将 committed_at 设为 started_at；归档 accepted_at 也来自该值。因此这些字段不能精确代表 ClickHouse 首次成功提交时刻；历史 API 探针只能记录本次首次看到，无法还原过去的首次可见时间。重复事件也未必产生历史变更。现有结果只能证明样本可追溯和处理延迟，不能证明每条事件在首次标准事件入库后 5 秒内可见。需要后续单独补齐计时与逐事件结果观测，再进行该项验收。

页面：390×844、1280×800、1440×900，分别访问终端、网络设备、哑终端、发现线索。12 个页面状态未发现横向溢出、违规空值提示、页面 JS 错误或 HTTP 失败；哑终端控件 nowrap/shrink 探针通过，截图保留。处理失败告警正常展示。未修改前端，本轮不重复构建或执行此前已通过的前端单元测试。
