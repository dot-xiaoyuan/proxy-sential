# 设备指纹库离线更新与多来源验收

现场运行不需要外网，不上传 MAC、UA、DHCP 或主机名。外部快照在构建机取得并转换；现场只加载已验证的离线包。当前现场目标为 `root@222.204.3.184`，发布与本地开发分开执行。

## v6 包与更新方式

v6 在既有 OUI、UA、DHCP、域名、品牌别名和项目规则上增加统一来源目录、转换结果以及原始快照和许可证。继续读取 v1～v5。要保留现场原有数据、只扩展新来源，使用：

```bash
go run ./cmd/proxy-sentinel device-fingerprint extend \
  --base /path/to/current-v5.tar.gz \
  --output /path/to/multisource-v6.tar.gz \
  --version offline-YYYY.MM.DD-multisource-v6
```

完整旧来源下载构建入口仍为 `scripts/device-fingerprint/build-offline-bundle.sh`。不要用开发机的精简引导数据覆盖现场完整库。现有包缺失的来源只能登记为未加载，不能把上游规模列为实际规则数。

管理员在“规则与特征库 → 设备特征库”导入包。系统验证路径白名单、重复文件、大小、SHA256、清单、来源版本、许可证材料、规则格式和正则后原子切换；加载失败保留上一有效版本，保留最近有效版本供回退。识别工作进程轮询本地激活版本，不访问外网。应用发布另按 `application-only-upgrade.md` 和项目 AGENTS.md 执行迁移核对与健康检查。

仅多来源规则变化时，按变化字段筛选最近七天端点，历史任务每批最多 100 个、间隔五秒入队，独立队列通道限额消费。原有数据变更继续走原回填机制。实时任务优先并合并重复更新，租约期间新增事件不会被已完成批次覆盖。

共 22,008 条处理记录，10,500 条可执行规则。Satori 的 test 分支、LibreNMS 的检测分支、WhatWeb 的静态匹配分别保存原始 ID，不能把转换记录数说成上游档案数。没有通过拆分同一 AND 条件增加规则数。

新增可执行规则中，107 条输出路由器品类，其中 68 条为设备自报证据；另保留项目自有 39 条路由器规则。这些数量不是可识别路由器型号数。OpenWrt 型号字典不会单独确认为路由器。网卡排除、AP/交换机冲突、通用 Linux 和公共证书均保留证据强度限制，Archer T/TX/TBE 不因 TP-Link 品牌成为路由器。

每条输入均保存转换状态、禁用原因、版本和原始 ID。当前待适配条目仍占相当比例：Satori 的部分 DHCP 消息类型、DHCPv6/TCP 等；WhatWeb 的动态 Ruby、主动路径请求及不支持表达式；p0f 的完整协议栈语义。程序不会执行外部脚本或发起扫描。已有管理数据中可用的 SNMP 声明式条件才参与执行。

源版本、下载地址、校验值、许可、原始输入及每条处理结果见 `internal/fingerprint/data/multisource-{catalog,provenance}.json`。目录包含原有六类来源；本次从 184 读取的实际旧包只有 11 条 OUI、1 条 DHCP 引导数据，NextDNS/HaGeZi 未加载，完整历史 Fingerbank 也不冒充已经导入。本次尝试刷新旧来源时网络超时，保留原包内容。

## 可重复构建与验证

转换依赖 Python 3、PyYAML 6.0.3 和项目 Go 工具链。不联网重建全部已分发快照：

```bash
python scripts/fingerprints/rebuild_catalog.py --output /tmp/fingerprint-rebuild
python -m unittest discover -s scripts/fingerprints -p 'test_*.py'
go test ./internal/fingerprint ./internal/controlplane ./internal/store
```

重建会比对完整目录和保存的原始输入。v6 包校验测试覆盖篡改、路径、许可证材料、兼容旧包和失败保留旧版本；识别测试覆盖上游可用样例、Archer 网卡、通用系统/证书、客户端与服务端归属、地址无法归属及跨库重叠。

2026-10-12 验证使用 184 的 `20261012T015609Z` 数据快照。因共享工作区存在其他任务并行修改，最终 Go 验证与本地运行使用仅包含本任务改动的独立源码副本和 `sentinel_fp_validation` 数据库，迁移到 102。共享环境的迁移 103 在应用后被修改，常规启动被校验拦截；未修改其迁移账本。共享工作区的 `TestEndpointRecentIPOrdering/first_seen_breaks_tie` 仍因并行设备清单改动失败，独立源码同项通过。

Go 全量测试及最终指纹、控制面、存储测试通过。前端 28 个文件、92 项测试，类型检查、生产构建及三视口测试通过。真实 API 下的四个视图在 390×844、1280×800、1440×900 完成截图和 DOM 探针，未发现页面溢出、按钮折行、禁止占位文案及接口错误。独立联调地址为 `http://127.0.0.1:18086`。

## 性能与覆盖实测

同一份 62,139 端点属性、同一旧包数据，比较关闭新目录与启用新目录的热进程回放：吞吐 47,911 → 45,712 端点/秒，下降约 4.6%；累计分配内存 885,662,504 → 914,615,696 字节，增加约 3.3%。已识别端点均为 28,016，冲突均为 3。新增来源命中 30,991 台，其中 Recog 30,986、Satori 34、跨库重叠 29；该快照没有增加已确认结论，不能把辅助命中当成新增识别成功。

数据库链路最终使用相同 1,000 台端点、单个实际消费 worker、三轮交替运行，并暂停本地回填工作进程：中位吞吐 40.62 → 43.49 端点/秒；整批排队 P95 的中位数 22,542.41 → 22,476.26 毫秒；每批画像和队列写入均为 3,000 行。新统计每批合并刷新增加 1 行写入，刷新耗时中位数 7.06 毫秒，没有逐匹配落库。中位累计分配 131,943,000 → 133,857,992 字节，增加约 1.45%。该有限样本存在运行噪声，不据此宣称扩库提高性能。两组均加载目录对象，这不是冷启动 RSS 对比，也不等同持续现场流量压测。

带本地后台回填负载的 100 台端点复核也保留在 `184-pipeline-replay-background-load.json`：中位吞吐 49.90 → 43.50 端点/秒，整批排队 P95 1,946.75 → 2,215.91 毫秒。两轮批量大小和竞争条件不同，不能横向比较吞吐或等待值。最终扩大批量是为减少小样本和后台磁盘竞争对结论的影响，未丢弃较差测量。

性能原始结果、包 SHA256、来源清单、UI 探针和限制见 `artifacts/multisource-validation/acceptance.json`，回放分项在同目录的 `184-*-replay-final.json`。历史重算按限额后台进行，界面实时显示进度；验收时尚未全部回填完成。

现场覆盖每分钟异步更新，分别显示当前规则—终端关联数、去重终端数及规则匹配次数。API 的 `count_semantics=current_rule_endpoint_relationships` 保留旧字段口径；新增 `evaluation_match_count` 累计成功画像计算中的规则匹配，`realtime_match_count` 和 `history_match_count` 区分实时与历史重算。计数自该版本启动后开始，不补造历史执行次数，以一分钟桶覆盖近 24 小时，不是逐报文计数；异常退出可能丢失尚未刷新的一分钟计数。计数在后台合并写入，采集热路径不增加同步落库。设备详情保留来源、规则、版本和实际命中片段；多个库对同一材料的命中不作为多个独立证据来源，也不直接触发处罚。
