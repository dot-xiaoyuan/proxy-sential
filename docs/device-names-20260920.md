# 设备名称采集与展示

2026-09-20 部署版本 `2026.09.20-device-names-r1`，前一版本保留在 `/opt/proxy-sentinel/releases/2026.09.16-device-lease`。

## 实现

- DHCP hostname/FQDN 和 mDNS A/AAAA 响应产生独立名称证据；发现协议查询不再复制为设备名称。Zeek 记录响应类型、名称、地址、TTL、SRV目标和解析器版本。
- mDNS 主机名称通过记录里的地址、传感器、园区和事件时间匹配唯一 DHCP 租约；DNS-SD 服务通过有效主机地址记录及事件时点租约关联，服务名称不参与主名称选择。未归属、冲突记录保留。
- 后台设备画像队列负责写入；已有批次失败重试沿用，名称记录以传感器/事件/来源/名称去重。每15秒最多重试100条待归属记录；DHCP更新时另行触发相关地址重算。名称不传入风险评分、设备计数或身份合并。
- 主名称优先人工备注、DHCP FQDN、DHCP hostname、mDNS hostname；当前有效证据优先于历史证据。同等级按时间、事件ID决定。七天窗口、mDNS TTL/撤回、租约到期及后续地址换绑限制有效期。
- 增量迁移054保存证据、备注和备注审计。旧属性只标记为历史属性，没有原始事件引用，不回填历史日志。
- 列表、详情共用选择逻辑，支持名称和已归属别名搜索；详情证据分页，事件引用可跳转。备注接口复用 endpoints:write、CSRF及只读限制，并写审计。
- 列表、详情在页面可见时15秒轮询，隐藏时停止后台轮询。移动端名称作为卡片标题；新增样式集中在 index.css。

接口：`POST /api/v1/endpoints/{endpoint_id}/name-note`（`value`为空清除）；`GET /api/v1/endpoints/{endpoint_id}/name-evidence?limit=50&offset=0`。列表和详情增加可选 `device_name`；OpenAPI已更新。

## 现场结果与限制

部署后五个相关服务active，readyz通过；PostgreSQL迁移至054，ClickHouse无需新增迁移。127个终端中73个显示历史名称；历史属性证据为73条hostname、12条FQDN（终端存在重叠），抽查5个终端列表/详情一致。

首次观察只有查询，继续观测后收到真实 DHCP 和 mDNS 响应。2026-09-20 14:38:52（北京时间）快照：127个终端中74个有名称，其中65个为历史名称、9个为当前名称；1个终端以mDNS名称作为主名称。新增DHCP证据14条、成功归属mDNS主机名证据18条、成功归属服务名称证据8条。210条主机名证据和16条服务证据尚未归属，其中主机名未归属记录188条为IPv6、22条为IPv4。数量是证据条数，不是独立设备数。

r1新增入库后队列处理耗时，63条新证据样本的最大耗时：DHCP FQDN 2358ms、DHCP hostname 2362ms、mDNS hostname 4064ms、服务名称4216ms。该指标是进入队列至名称处理的耗时，不包含页面轮询；不能用含DHCP聚合等待及重试的事件时间差代替。小样本满足30秒处理目标，不等于持续负载SLO验收或未归属记录都能在30秒内获得身份。现场真实响应链路已得到正例，IPv6和缺少唯一租约的覆盖问题仍保留。

最终现场记录为 `artifacts/device-names-20260920/field-r1-final.txt`。这些变化主要补齐名称展示与证据链，不按73到74的变化承诺总体识别率。

观察期间原画像队列出现满队列日志。当前实时队列仍沿用原画像处理机制，停用历史扫描时队列溢出后的自动恢复不作零丢失保证；100条待归属重试上限可能使积压延迟超过30秒。mDNS归属目前以唯一有效DHCP租约为依据，没有有效租约时保持未归属，不使用当前IP直接兜底。后续需用真实新增响应和租约持续验证覆盖、冲突和延迟。

## 关闭展示与回退

在服务运行环境设置 `PROXY_SENTINEL_DEVICE_NAMES_DISABLED=true` 并重启控制面，可隐藏名称列和名称区域；采集证据继续保留。清除此变量后恢复展示。

恢复旧版本：将 `/opt/proxy-sentinel/current` 原子切换回上述保留目录，再重启 control-plane、ingest、risk-materializer、device-signal、zeek 服务并检查 readyz。054是新增表迁移，回退旧程序不删表、不删名称证据。发布脚本记录在 artifacts 目录，切换失败时自动恢复前一版本。

隔离测试容器已清理；生产未写入合成名称或人工备注。另保留初次名称版本 `/opt/proxy-sentinel/releases/2026.09.20-device-names`，可回退至该版本或原9月16日版本。

## 名称可用性修正（2026-09-20）

自动名称入库前过滤 UUID、长纯十六进制标识、纯 MAC/IP、纯数字首标签和不可用转义文本；DNS-SD 服务实例必须有合法服务后缀且实例部分可读，始终不参与主名称选择。保留中文、DESKTOP 等可读前缀、下划线名称和带 MAC 后缀的设备描述。人工备注独立保留。读取主名称时再次过滤，避免旧证据回显。

mDNS 仍只接受响应，以记录地址而非查询方/报文发送者认领设备，要求同传感器、网络范围、事件时刻的唯一有效租约；新增 A/AAAA 地址族匹配和回环地址拒绝。TTL、撤回、冲突和服务实例隔离沿用回放验证。协议自报名称不是经过认证的真实身份。

迁移 055 清理自动名称证据，不删除原始标准事件；迁移 056 修正首版标点过滤过严导致的可读 DHCP 属性遗漏，恢复为明确标记的历史属性，不伪造事件引用。现场清理前有 162 条不透明 mDNS 主机名证据、56 条不透明服务名证据，清理后均为零。当前发布验证记录见 artifacts/device-name-quality；包含 Go 竞态测试、隔离 PostgreSQL 回放、幂等清理和属性恢复测试。此次后端修正保留此前 IP 第一列布局。
