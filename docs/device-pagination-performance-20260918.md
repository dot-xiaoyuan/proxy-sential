# 30 终端画像第二页性能修复

截图请求 `/api/v1/devices?window=24h&limit=20&cursor=20` 曾 10.02 秒返回 500，重试 3.29 秒。现场分页 ID SQL 本身仅 0.232ms；旧 IP 历史批量读取执行计划耗时 4935ms，涉及约 4000 条记录。查询用 host(ip) 做时间相同时的排序，但旧索引使用 inet 字段，需额外排序和大量随机回表。每个列表请求还重复聚合当前页的品牌证据，尽管筛选选项已经加载了同一识别快照。

新增 PostgreSQL 043 版本迁移：三个列表摘要覆盖索引，IP 索引保留文本 IP 稳定排序。列表仅投影画像实际使用的账号、IP、接入标识与时间，保留每终端最多 200 条记录边界及现有响应字段；完整历史与原始引用仍在详情路径。识别证据复用按识别规则和指纹版本隔离、至多五秒的目录快照，在新读取的独立设备信号上重新推断，不覆盖实时身份和归属。目录未包含的新终端单独读取证据。

已更新 30 正式后端。PostgreSQL 043、ClickHouse 016；迁移/追平成功，四个常驻后端服务更新，最终 readyz 全部启用组件 ready。启动过程发生连接拒绝和 503，脚本按既有重试后成功。未备份、未删除现场业务数据；前端未改动。

在 30 本机通过已认证的 HTTP 请求测量，读取完整响应体；现场持续采集保持运行。各页分别 20 并发、200 次正常非空业务结果，检查分页数量、总数、品牌筛选值、识别统计时间不超过五秒。测量不含用户浏览器到 30 的网络耗时。
