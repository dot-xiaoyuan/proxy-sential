# 终端画像与重复 IP 核对（2026-09-17）

## 展示与字段含义

终端画像仍按终端身份分页，一条记录对应一个 endpoint_id；MAC 是列表的主要身份标签。IP 相同不会合并记录，不同 MAC 也不直接等于不同物理设备或共享上网。

接口保留 current_ip 字段，含义改为“最近观测 IP，不保证当前在线”。从非空 IP 历史中按 last_seen 降序、first_seen 降序、IP 文本升序选择；时间按实际时刻比较。无记录返回空值。所有 IP 历史仍保留，数据库不需要迁移。

列表以 IP、MAC、品牌/型号、账号/责任人、接入位置、最近观测、详情入口排列。终端 ID、登记、置信度与完整证据留在详情；覆盖率、生态规则及归属率告警默认折叠。品牌保留“推测”“厂商”“线索冲突”等必要说明，不把生态访问推断为硬件确认。

## 30 上的只读核对

目标为 192.168.0.30，当前发布链接为 /opt/proxy-sentinel/releases/2026.09.16-device-lease。本次仅读取 PostgreSQL 和原始采集日志，没有修改服务、部署程序或清理数据。SQL 在 READ ONLY 事务内执行，设置 10 秒语句超时；以下结论仅覆盖抽样记录。

| 样本 | 核对结果 | 分类 |
| --- | --- | --- |
| 00:0c:29:2a:37:8d | 第一页抽样中旧排序选 192.168.0.1；当时最新观测为 192.168.0.57 | 展示选择错误 |
| 192.168.0.1 | 2026-09-17 02:01:40 UTC 同时被 TTL 记录关联到 00:0c:29:2a:37:8d 与 00:e0:67:2a:4f:4c | 重叠观测关联，不能确认 IP 实际归属 |
| 00:0c:29:2a:37:8d 的 DHCP | office-30、空 campus_id，ACK 指向 192.168.0.57，租约为 01:28:24.473087–03:28:24.473087 UTC；该次查询未发现 192.168.0.1 的租约记录 | 与 TTL 的其他 IP 关联存在归属疑点 |

原始 TTL 日志为 /opt/proxy-sentinel/data/device-signals/ttl.jsonl，采集器为 packet-sidecar，传感器 office-30，接口 ens1f1。样本的 collector_instance_id 为空，未包含 campus_id/VLAN 等范围信息。192.168.0.1 的认证会话查询未返回记录。

这些记录不能统一解释为 DHCP 先后复用，更不能判定共享上网。可能存在转发链路 MAC 被关联为终端 MAC 的问题，但当前证据只能确认重叠观测和信息不足；进一步归责需要同范围有效租约、认证会话或原始报文。此次不改采集归属逻辑，也不隐藏重复记录。

先后复用情形由标准事件回放覆盖：同一终端改变 IP，之后另一 MAC 使用该 IP，保留两条独立终端画像。

## 验证与更新

顶部新增操作系统与品牌筛选，支持搜索、清除和组合选择，改变筛选时回到第一页。/api/v1/devices 接受 brand、os_family 精确匹配参数（大小写不敏感），响应增加 facets.brands 与 facets.os_families。选项来自全部终端识别线索，不随当前页、搜索或选择收窄；unknown 对应“未识别”。系统与品牌线索不保证已经确认硬件身份，品牌优先使用已确认识别，其次为可展示的推测，再次为已有识别线索；冲突记录归入未识别，独立域名推测保留其推测含义。

数据库模式批量读取终端识别元数据和必要的域名证据，避免为生成选项逐个读取终端 IP/会话历史；筛选在 SQL 分页之前执行。30 上同类域名聚合查询只读核验返回 481 组线索，耗时约 78ms（单次读数，不是完整接口性能验收）。文件回放模式同样先读取完整标准事件，再按终端筛选和分页。此功能需要同时更新后端与前端，无新增迁移。

覆盖最近 IP 与地址排序不一致、时间与 IP 并列、时区比较、空 IP 历史及 IP 复用的后端测试；前端覆盖识别/推测/冲突/未知、复制、搜索、分页、详情跳转，以及三种屏幕尺寸的截图和 DOM 样式检查。

开发阶段不做备份。本次需要更新后端程序和前端并重启使用该程序的服务；仅执行 make deploy-ui 无法使后端最近 IP 修正生效。无新增数据库迁移；本次未执行服务器部署。


### 品牌、MAC 厂商与系统语义修正

撤销 MAC 厂商回退为品牌的做法。品牌筛选取 brand、独立的品牌推测或明确标注的设备厂商 MAC 品牌参考；不再将任意 vendor 直接当作品牌。主列表不直接使用 vendor 作为品牌；设备厂商参考采用单独的 brand_reference 字段及“MAC 厂商线索”标签。MAC 下单独展示原始“MAC 厂商”名称，提示可能是网卡、主板或虚拟接口厂商。详情统一标为“MAC 注册厂商”。

30 的只读核对发现 hostname=office-mac41.local、vendor_class=darwin 的终端，原有规则未处理这一组合。补充标准信号的保守 macOS 推测：同时满足 DHCP vendor class 精确为 darwin 和独立的 Mac 主机名词段时，OS 为 macOS、置信度 0.65，保留组合证据，不生成品牌、型号。Darwin 单独出现、主机名单独出现、machine 等字符串均不触发。已存在系统识别优先，DHCP 指纹冲突继续保留冲突标记。该补充随程序生效，兼容已安装的离线库，不需要重写历史或更新库文件。

列表展示系统线索，低于 0.8 标“系统推测”；系统筛选仍由全部终端实际识别结果生成，不能由 Apple 品牌或 Apple 服务域名反推 macOS。


### 恢复设备厂商的 MAC 品牌参考

新增可选 brand_reference，包含标准品牌名、原始厂商、来源 mac_vendor、参考评分 0.6 及解释。白名单仅覆盖有明确设备品牌名称的注册厂商（例如 Huawei、Vivo、OPPO、Apple）；Intel、Realtek、VMware、Parallels 和未知厂商不生成品牌参考。MAC 缺失、随机 MAC、厂商置信度低于 0.8 时不生成参考。brand、brand_confidence、型号与系统识别保持独立，MAC 参考不能参加域名品牌置信度融合。优先展示已确认设备品牌，其次域名推测，最后 MAC 品牌参考；冲突时不以 MAC 参考掩盖冲突。参考品牌进入全局筛选，详情提供单独的“MAC 品牌参考”说明。程序与前端一并更新，无数据库迁移。
