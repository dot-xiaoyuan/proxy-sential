# 发现重复写入退役（2026-11-03）

用户在完成 P0 只读定位后要求尽快停止旧链路和重复投影。本次以单个 r69 候选完成切读、退役，若仍净积压则停止追加发布并分析剩余瓶颈。此前[只读诊断](p0-backlog-root-cause-20261103.md)保留为变更前证据。

## 原因与边界

流式迁移时为对比保留了影子链路，但页面随后直接依赖影子当前态，双写没有随切读完成退役；消费者和聚合器还固定在旧发布目录。它已成为实际业务依赖，不能解释为当前仍必需的验证开销。逐个修复慢点而没有核对整条链路的运行版本与退役条件，也是前期迭代遗漏。

| 路径 | 本次处理 |
| --- | --- |
| stream discovery facts/state、变化历史与原文/清单 | 保留，为当前事实、查询与恢复的权威来源 |
| discovery Kafka 消费组 | 保留同组同偏移，只写 normalized_events，继续供活动与风险查询使用 |
| discovery_service_facts_shadow、ClickHouse discovery 影子事实/回执 | 停止新增写入，旧数据原位保留 |
| discovery_device_current_shadow 及其 Redis 同步 | 页面改读 stream 当前态后停用聚合器，保留旧表与配置 |
| 身份、共享、路由、唯一原文与案件证据 | 本次不退役，不移动截止点、不取消新输入 |

## 实现与验证

- 控制面使用 `PROXY_SENTINEL_DISCOVERY_CURRENT_SOURCE=stream`，列表、筛选、SNMP 候选及覆盖状态退出 shadow 表依赖。分页只取已生成的当前设备文档；原有识别摘要附加逻辑保留。
- 消费者 `--normalized-only` 不创建 PG 事实 sink 和 CH 影子 sink；标准事件持久化失败仍阻止提交 Kafka 偏移，沿用原消费组恢复。
- PG226 为当前行增加 `(epoch,last_seen DESC,device_key)` 部分索引。现场只读计划已证明原索引为第一页扫描大量失效行，并可能把事实 EXISTS 拉起为全代次扫描；部分索引配合相关子查询边界消除此路径。新增索引会随当前状态变化维护，保留期与当前状态一致，无新增事件副本和结果版本；具体大小和切换后增长在现场记录。
- 列表进度只读取当前态版本，不等待历史回执扫描，不据此宣称源队列或归档追平；总数独立限时，失败不返回伪造的 0，也不使有效列表失败。
- 应用更新增加 `--preserve-discovery`，保持已有采集进程与内存队列，避免为只读路径修改而中断采集。消费者作为固定版本服务单独更新并核对实际进程。
- 针对 discovery/controlplane/eventbus 的测试已通过；Go 构建与 vet、发布脚本的自然重启/队列保护检查通过。没有启动本地完整数据库栈，没有在 184 造数压测。
