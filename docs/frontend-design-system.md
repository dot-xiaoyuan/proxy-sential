# Proxy Sentinel 前端设计系统

## 1. 基线与适用范围

Proxy Sentinel 采用 [Ant Design v6](https://ant.design/) 作为组件与 Design Token
基线，采用 [Ant Design Pro](https://github.com/ant-design/ant-design-pro) 和
[ProComponents](https://github.com/ant-design/pro-components) 的企业后台信息组织方式。
两者均为开源方案，且与项目现有 React 19、Ant Design 6、TanStack Query 技术栈一致。

本项目不再并行引入 Arco、Semi、Carbon 或其他完整组件库。确有能力缺口时，先封装
Ant Design；只有经过设计评审和包体评估后，才允许按需引入 ProComponents 组件。

规范适用于所有页面、详情、列表、卡片、筛选区、弹窗、抽屉、图表、状态提示和通知。

## 2. 设计目标

1. **任务优先**：用户进入页面后先看到当前任务的筛选、关键状态和数据，不用先阅读大段说明。
2. **证据优先**：确定且高置信度的内容优先；推测信息弱化并保留依据，不包装成确定结论。
3. **高密度但可扫视**：运营后台以列表和表格为主，卡片只用于独立对象、摘要或移动端重排。
4. **状态语义稳定**：同一颜色只表达同一类语义；颜色不能是唯一的状态载体。
5. **响应式无损**：窄屏重排信息，不通过整页或主数据区横向滚动解决布局问题。

## 3. Design Token

主题唯一入口为 `frontend/src/app/theme.ts`，通过 `ConfigProvider` 和 Ant Design CSS
变量输出。业务组件不得创建第二套主题对象。

| 类别 | 基线 |
| --- | --- |
| 主色 | `#2257a7` |
| 页面背景 | `#f8fafc` |
| 容器背景 | `#ffffff` |
| 常规边框 | `#e2e8f0` |
| 主文字 | `#0f172a` |
| 次文字 | `#475569` |
| 基础字号 | 14px |
| 辅助字号 | 12px |
| 基础圆角 | 8px |
| 基础控件高度 | 32px |
| 间距序列 | 4、8、12、16、20、24、32px |

风险红、告警橙、观察黄、正常绿是业务语义 Token，只用于相应状态，不作为装饰色。
新增颜色或尺寸前应优先复用 Ant Design Token 或现有 `--ps-*` 语义变量。

## 4. 页面结构

- 顶部应用栏保持单行，页面内容独立滚动。
- 页面标题区只放标题、必要上下文和主要操作；桌面高度原则上不超过 72px。
- 页面说明默认放在主数据之后或折叠区；错误、冲突、权限阻断等关键信息例外。
- 标题后应尽快进入筛选或主数据。移动端主内容原则上在首屏高度的 35% 以内出现。
- 同一页面不重复放置侧栏入口、页头入口和内容入口。

## 5. 数据展示

### 表格与列表

- 992px 及以上可使用复杂表格；小于 992px 的复杂表格必须转换为纵向列表或卡片行。
- 不允许页面级横向滚动。确需保留的代码、原始 JSON 和协议字段必须限制在局部容器内。
- IP、MAC、UUID、Hash 使用明确截断或 `overflow-wrap:anywhere`，不得挤压按钮和状态。
- 分页器必须与内容同宽，在 560px 以下隐藏非必要页码和跳页控件。

### 标签与状态

- `Tag` 只用于“标记和分类”，不得承担段落、说明或整行容器职责。
- 标签宽度必须随内容，不得因父级 `flex/grid` 拉伸成整行。
- 同一对象首屏最多突出 2 个高价值标签，其余状态移到次要信息或详情。
- 标签文字不折行；长解释不用标签，改用次要文本或折叠详情。

### 缺省与低置信度信息

- 缺失字段显示空内容，不展示横杠、“未知”“未获取”“未识别”等占位词。
- 可以省略的空字段直接隐藏；真实错误、冲突和阻断状态必须明确显示。
- 低置信度线索使用次要文字或弱化标签，并保留可追溯依据。

## 6. 响应式断点

| 视口 | 用途 | 必须验证 |
| --- | --- | --- |
| 390×844 | 手机 | 单列、操作换行、无页面横向溢出 |
| 743×774 | 小屏/现场窗口 | 复杂表格转列表、分页可用、抽屉不遮满屏 |
| 1280×800 | 笔记本 | 高密度表格、首屏主数据、操作栏完整 |
| 1440×900 | 桌面 | 信息层级、留白和列宽平衡 |

## 7. 组件使用规则

- `Button`、`Tag`、Badge、菜单项和操作链接必须 `white-space:nowrap`、`flex-shrink:0`。
- 操作组必须允许换行并使用 8px 左右间距。
- 页面容器和主要卡片使用 8px 圆角、`#e2e8f0` 边框；禁止黑色重边框和大面积深背景。
- JSX/TSX 禁止硬编码内联样式。新样式进入组件 class 或主题 Token。
- 图标使用 Ant Design Icons 或统一 SVG；不用 Emoji 充当业务图标。
- 选中态文字与背景对比度不低于 4.5:1。

## 8. 文案与交互

- 标题描述对象，按钮描述动作，避免重复“当前”“相关”“信息”等无效词。
- 删除、处罚、策略生效等高风险动作必须说明对象和影响范围，并提供确认与结果反馈。
- 加载、空态、失败、权限不足分别处理，不用空白页面代替状态。
- 帮助说明按需展开，不能挡在用户的主要任务之前。

## 9. 验收门槛

每次前端改动必须完成：

1. `pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build`。
2. `pnpm ui:audit`，覆盖 390×844、743×774、1280×800、1440×900。
3. 截图检查、DOM 溢出探针、设计规范逐项对照。
4. 检查标签是否内容宽度、按钮是否折行、长标识是否溢出、主内容是否进入首屏。
5. 新增共享组件或视觉 Token 时同步更新本文档和对应自动化测试。

评审时以“用户任务是否更快完成”为优先，不以组件数量、装饰复杂度或页面填满程度作为质量标准。
