# 认证事件可靠接收与异步处理

## 责任边界

Redis 原队列 → processing 中固定批次 → PostgreSQL 收件箱 → 身份短事务与独立原始事件导出 → ClickHouse 派生处理。

新入口 `POST /api/v1/integrations/identity/event-batches` 只鉴权、校验、标准化和持久接收。返回 202 之前必须提交 PostgreSQL 事务；响应必须包含协议 2、批次 ID、SHA256、记录数、`durably_accepted=true` 和可靠接收时间。202 不表示身份已处理。旧 `/events` 保留同步语义，失败批次不能返回成功状态，旧发送端必须验证匹配的 completed 结果。

processing 的 WATCH/MULTI/EXEC 事务冻结原始前缀、首次标准化时间、Redis 实例、作用域和来源版本；发送前再持久保存标准化请求、协议、批次 ID、校验值和记录数。未确认批次重试时不能追加新消息。确认需要有效租约代次和完全相同的前缀。格式异常消息的原文进入同权限隔离队列，指标单列，不能当作成功。`--restore-processing` 拒绝恢复含有效租约或批次清单的 processing，避免破坏幂等重试依据。

作用域为 `(source,sensor_id,campus_id,access_domain)`。收件箱容量由 `PROXY_SENTINEL_IDENTITY_INBOX_MAX_RECORDS` 控制，默认每作用域 100 万条；身份或原始导出任一待处理量达到容量，接收返回 429，Redis 继续保留消息。持久记录及未完成任务不参加普通年龄清理。

## 工作进程

每个 `read-model run --lane identity --sensor-id SENSOR` 同时启动独立的身份收件箱、原始导出和全量校准循环。184 的 NCU 实例是 `proxy-sentinel-ncu-identity-materializer.service`，不是桥接服务 `proxy-sentinel-ncu-identity-sync.service`。

身份领取使用作用域租约及递增代次。处理批量初始 100、范围 25–500，2 秒事务预算，超时缩小、连续稳定后增大。标准化在请求端完成，事务不访问 ClickHouse、设备历史或外部网络。不可变身份事实、增量应用记录、有效地址/会话/账号引用及处理进度原子提交。最终短暂锁定摘要行并重新验证代次、租约有效期和投影版本；已失效进程的全部身份写入回滚。接收端无需等待身份地址写入。

当前计数仅在地址引用、会话引用的 0↔1 转换时调整。同一会话的多地址只计一次，旧事件不能回退当前状态，同时间冲突下线优先。作用域及登录代次独立，重放不重复计数。

原始导出使用独立租约，不跨 ClickHouse I/O 持有 PostgreSQL 事务。稳定事件 ID 复用已有 ClickHouse 去重写入，导出回执丢失可恢复。权威身份积压时暂停导出，保留待导出任务及计数，追平后自动恢复，避免 ClickHouse 写入争用同一磁盘。设备实体、绑定历史和旧版 `account_sessions` 显示兼容投影继续由派生物化器更新；它不再写已切换作用域的权威策略身份事实、当前身份和计数。普通 DPI 路径保持原职责。NCU 与已启用可靠接收的来源禁止按积压年龄跳过游标。

历史窗口保持已有合并语义，通过完整绑定键的紧凑头表定位，不再在实体锁内扫描大历史表。原始证据继续保留。

## 全量校准

只有经过完整性验证并完整保存的快照才能进入校准。后台建立私有版本、一次性构建引用计数，并重放快照边界之后已提交的增量。在确认处理检查点没有变化后，短事务切换版本和统计；检查点移动则继续追平。失败保留上一成功版本。旧快照不会覆盖更新事实。

桥接服务启用新协议后，快照保存成功还需查询 publication 回执确认该快照已经发布，才更新来源成功状态。未完成旧事件队列的责任不能通过来源切换丢弃。

替换或失败的私有版本进入清理队列，按精确作用域/版本每轮分批清理地址、会话引用和账号引用。始终保护当前版本和有效构建版本；清理不涉及完整快照、不可变事实、批次回执或收件箱。

## 页面与动作准入

`GET /integrations/identity/bridge` 仅查配置、心跳、单作用域摘要和派生游标，不扫描会话明细做去重。账号和会话数量表示已处理状态，附统计时间及批次进度。Redis 待接收、待确认、服务端身份待处理、原始导出待处理分别展示，不能相加成总积压。

队列由后台每 5 秒采样，与页面是否打开无关。失败保留上次值及时间并标记过期，不能写零。页面进入或手动刷新才请求；取消定时、窗口聚焦和网络重连触发。连接器和认证状态并行加载、独立错误；刷新失败保留上次成功结果。

真实动作在原有权限、只读、影子模式、冷却、熔断、人工复核、审计和撤销保护外，还要求当前来源版本匹配、心跳和采样在 15 秒内、队列及隔离责任已清、身份追平已接收检查点、全量校准成功且覆盖仍有效。发出动作前沿用最终复核和登录代次检查。184 保持 `read-only=true`，验收不执行真实处罚。

## 分阶段上线与回退

1. 重新核对 184 主机、身份、现场提交、current/previous、服务、空间、配置和迁移账本。保留其他线程现场改动。108、109 是兼容性新增迁移，使用完整安装迁移流程；是否备份遵循当前用户明确指令及现场规范，不能略过迁移校验。
2. 先发布兼容版，桥接 `--durable-events=false`，新工作进程和校准先就绪。停止旧同步发送后检查旧在途请求已结束；启用新协议前，所有 NCU 物化进程必须使用新二进制。
3. 将相同受测提交构建为第二个唯一应用版本，核对所有迁移校验后应用升级。让 previous 指向支持协议 2 的兼容版，再通过桥接服务参数启用 `--durable-events=true`，禁止新旧权威写入方并存。
4. 发布持有同一锁并检查 expected-version；若现场变化，重新核对源码和包，禁止旧包覆盖。保留系统单元配置、账号凭据和只读模式。单独重启并验证 NCU 桥接 18082 和 NCU 物化器进程版本。
5. 已启用异步确认后，不得直接退回不认识收件箱的旧版。先用 `PROXY_SENTINEL_IDENTITY_DURABLE_ACCEPT=false` 停止接收，让 Redis 保留新消息，兼容工作进程继续排空已确认任务。只回退到支持协议 2 的兼容版本；不要将桥接直接改回旧 `/events` 发送。

## 历史失败恢复

使用现场受保护环境中的 PostgreSQL DSN，先执行只读预览：

```sh
proxy-sentinel identity-recovery --source ncu-srun4k --sensor-id ncu-auth-redis
```

确认来源已经切换且实时链路正常后，增加 `--apply`。工具基于旧失败账本保留的标准事件，按作用域/事件 ID 去重，使用确定批次 ID 和恢复来源记录。仅在实时身份队列空闲时导入每批 25 条，批间至少 1 秒；重复执行安全。它不会把旧 failed 行直接改成 completed。

分别检查 `pending_identity`、`raw_export_pending`、`already_applied` 及缺失证据列表。没有保留标准事件的失败批次单独报告，不能凭一次 HTTP 成功或队列清零宣称恢复完成。隔离原文只能在受保护环境修正并回放，禁止写入普通日志。

## 验证

隔离 PostgreSQL 的回放覆盖丢回执、重复与冲突批次、容量、跨域、失效租约、处理阻塞仍可接收、双栈计数、乱序、构建中到达新登录、发布前崩溃、导出确认丢失、派生写入职责、恢复幂等和动作门禁。锁住全部会话明细表后，摘要仍需在 300ms 内完成。

隔离 Redis 覆盖稳定前缀、重启、双消费者、过期确认、失败采样和恢复保护。故障注入不在业务数据库进行。持续压测按 35,000 会话规模、100 条标准事件/秒执行 30 分钟，故意阻塞设备历史写入并暂停导出，分别验证接收、身份事务和身份进度。生产验收另记录真实 HTTP p95、后台收敛和三视口结果；隔离压测数字不能替代现场实测。
