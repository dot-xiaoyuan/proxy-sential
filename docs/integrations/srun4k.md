# 深澜 4K 接入

## 使用方式

在“旁路处置网关”选择“配置 4K 接入”，只填写 4K 地址。全量校准周期可选，默认 6 小时，范围为 1–168 小时。连接器 ID、身份来源 ID 和采集标识由 Sentinel 生成。

保存后服务端依次只读检查授权库、Redis 与北向 API。首次启动及到达校准周期时自动执行完整同步，也可以在页面立即同步。上线、下线事件采用独立标准事件契约；具体传输渠道完成对接前，页面显示“等待事件通道接入”，服务端阻断真实动作。

## 部署配置

页面不接收端口、协议、库名、数据库账号、Redis 密码或证书。它们由 30 侧服务部署配置提供：

- `PROXY_SENTINEL_SRUN4K_DATABASE_PORT`，默认 `3506`
- `PROXY_SENTINEL_SRUN4K_DATABASE_NAME`，默认 `srun4k`
- `PROXY_SENTINEL_SRUN4K_DATABASE_USERNAME`
- `PROXY_SENTINEL_SRUN4K_DATABASE_PASSWORD`
- `PROXY_SENTINEL_SRUN4K_DATABASE_TLS`
- `PROXY_SENTINEL_SRUN4K_REDIS_PORT`，在线会话 Redis，默认 `16380`
- `PROXY_SENTINEL_SRUN4K_REDIS_CATALOG_PORT`，产品与控制关系 Redis，默认 `16382`
- `PROXY_SENTINEL_SRUN4K_REDIS_PASSWORD`
- `PROXY_SENTINEL_SRUN4K_REDIS_TLS`
- `PROXY_SENTINEL_SRUN4K_API_SCHEME`，默认 `https`
- `PROXY_SENTINEL_SRUN4K_API_PORT`，默认 `8001`
- `PROXY_SENTINEL_SRUN4K_API_CERTIFICATE_FILE`，可选的北向服务器信任证书
- `PROXY_SENTINEL_SRUN4K_MAX_SESSIONS`，默认 `100000`

MySQL 账号只需读取 `authorization`；Redis 账号只需读取在线会话、产品和控制关系。Sentinel 不向 4K Redis 或 MySQL 写入数据。

与旧 `dpi-analyze` 一致，在线清单和产品目录读取不同的 4K Redis 实例；不是从在线实例的空产品清单判定产品全部停用。两个端口均可由部署侧覆盖，使用部署侧 Redis 密码。用户组通过北向 API 按每页 100 条查询，避免 4K 拒绝超出上限的分页参数。

Redis 密码通过 `PROXY_SENTINEL_SRUN4K_REDIS_PASSWORD` 注入，不硬编码到程序、前端或公开配置。30 当前使用独立的 `/opt/proxy-sentinel/config/srun4k-secrets.env`（权限 `0600`），由 control-plane 的 systemd `EnvironmentFile` 加载；更新程序不会覆盖此文件。修改密码后重启 control-plane 即可生效。北向 API 的证书也在部署侧提供，不跳过 TLS 校验。

已配置过 4K 数据库的实例可继续复用相同主机的加密配置；部署预置的完整数据库凭据优先。新接入页面仍只管理地址与校准周期，不返回任何密码。

## 数据与策略边界

- Redis 在线清单形成账号、IP、登录代次、会话、产品、用户组、VLAN、MAC、设备和 NAS 关联。
- Redis 产品、控制策略及绑定关系仅形成策略匹配目录和来源证据，不生成防代理条件或动作。
- 北向 API 的用户组接口补充真实组名。
- 防代理策略由 Sentinel 管理，范围可以选择产品、用户组、VLAN和账号；全部设备、电脑、移动设备阈值按 OR 关系判定。
- 消息提醒写入 Sentinel 模板发送队列；强制下线调用 4K 在线下线；用户禁用调用 4K SafeDisable，并由 `disable_time` 控制到期恢复。当前 4K SDK 没有独立恢复方法，因此人工撤销不会伪造“已经恢复”。
- 策略默认保存为停用。选择“真实执行”并打开策略开关后才允许生成真实动作；选择“仅记录”时只形成影子记录。

所有动作在发送前重新检查策略修订、开关、风险状态、当前登录代次、身份关联、全局紧急停止、连接器熔断及事件通道状态。双栈地址共享同一认证会话，设备和会话统计不会重复。

## 同步失败与审计

手动同步与周期同步使用同一失败登记路径。连接检查失败记为 `integration.srun4k.test`；完整同步失败记为 `integration.srun4k.sync`。同步内的连接检查失败会保留检查与同步两种审计，并保留具体失败渠道。同步失败不刷新 `last_synced_at`，也不将失败登记时间写成新的 `last_tested_at`；实际执行的连接检查仍更新自己的检查时间。

单次失败登记的状态更新与审计写入共用最多三秒的上下文。原请求超时或取消后仍尝试登记，并保留原操作人；数据库阻塞时按预算退出，状态或审计写入未完成会在服务日志中明确记录。日志不输出上游错误原文或部署凭据。不能把日志中的写入尝试当作已经保存的数据库审计。

身份状态汇总按当前自动注册的 4K 校准周期判断快照新鲜度，达到三倍周期显示中断；这与事件通道等待状态分别判断。策略读取仅在一次读取内复用相同身份范围的注册查询，每次执行前检查都会重新读取当前配置。

成功的只读检查将健康状态、检查时间和成功审计写入同一 PostgreSQL 事务；更新、审计或提交失败时不返回成功结果，也不留下单独的健康状态。结果保存最多等待三秒，并遵守原请求的取消与更短截止时间。此类结果保存失败返回 503，公开错误不包含数据库原始异常。

提交时核对本次检查的主机、来源、采集标识与校准周期，并拒绝覆盖较晚的检查结果。成功响应使用提交时的事件通道状态，避免旧快照显示已就绪。旧配置的结果被拒绝后，同步失败审计仍可尝试登记，但不会据此把当前新配置标成连接失败。这些检查不替代真实动作发送前的策略、身份与授权门槛。


## 更换网关地址

同一个接入可以修改地址。地址实际发生变化时，服务为来源与采集标识生成新版本，清空本接入的检查时间、同步时间和统计摘要，事件通道恢复等待状态。连接器恢复影子模式，旧网关的影子验收计数与就绪状态不再适用于新网关；关联的托管身份源配置保留但停用，需重新核对后配置。

历史身份快照、产品及用户组目录继续留在原来源中，不搬迁、不删除。原来源不再自动注册，来源限定策略不会自动改指向新网关。返回曾使用过的地址也会生成另一来源；相同地址重试保存以及只调整校准周期保留当前来源。

地址与来源调整、摘要和验收重置、旧身份源停用及保存审计在同一事务中提交。旧地址上的只读检查或完整同步晚到时，不得修改当前接入的状态、时间或摘要；旧失败单独记入审计。完整同步结果及成功审计同样原子提交，结果保存最多三秒且遵守原请求截止时间，失败返回 503。成功响应读取提交时的事件通道状态。

运行时刷新先撤销旧凭据引用，并用进程内版本检查阻止较慢的旧刷新覆盖新配置。此机制不会撤回已经送到上游的请求，不替代真实动作发送前的重新授权检查。


## 用户组目录的顺序与空目录

每次完整用户组查询以请求起始时间作为本次观测序列，记录完整目录、内容摘要与接收时间，包括空数组。每个来源独立串行提交目录与快照；不同来源可独立写入，不在上游网络读取期间持有目录事务锁。

晚到的较早目录保留在快照历史中，但不修改当前 active 目录，完整同步返回 409 并单独审计为 superseded。较新的空目录同样具有观测水位，旧结果不能随后重新激活已移除的组。相同观测时间与相同内容可幂等重试，数组顺序不同不构成变化；相同时间但内容不同返回冲突，保留原目录。过期或冲突结果不据此将当前连接标成失败，也不记为完整同步成功。

目录、快照和目录提交审计在同一事务中发布。迁移仅导入原目录作为明确标记的 legacy_import 基线；保留原行、名称、active 标志及时间，不声称这些基线是重新请求得到的上游快照。来源变更后原来源的组目录与快照继续保留。

该顺序保护仅针对用户组目录。在线身份与产品目录各自按已有观测时间处理，不把它当作完整同步各阶段的单一原子事务；同地址健康结果与完整同步摘要另用任务序号保护，不共享用户组观测时间。


## 连接结果与同步摘要的回写顺序

检查或完整同步在第一次上游读取前取得数据库递增序号。一个完整同步和它内部的连接检查共用序号；重新读取配置时范围变化则拒绝继续旧任务。序号跨数据库连接与进程递增，不依赖完成时间或机器时钟；序列禁止缓存分段和循环。

健康状态、检查结果与同步摘要分别保存最新已应用的任务序号。旧任务成功或失败晚到时，不得覆盖已应用的较新结果。失败登记保留审计；旧配置与较旧观测分别记为 failed_for_previous_configuration 和 superseded。没有合法序号的结果不会更新状态。相同完整同步内部先检查成功、随后同步失败仍能如实记为失败。

同步摘要较新但连接已有更晚的失败观测时，可以提交完整摘要与成功审计，同时保留该连接失败。同步响应返回实际 connection_state，只有连接和事件通道都 healthy 时 enforcement_ready 才为 true；其他真实动作准入条件仍另外检查。弹窗在同步后刷新当前状态并移除较早的检查展示，不会把完整目录同步成功当成最新连接仍然正常。

079 迁移给旧结果增加零序号基线，不改写原状态、错误、时间或数量；更换主机时序号与摘要一并清零，且旧任务仍受来源版本校验约束。成功结果与审计继续原子保存，失败登记继续使用原有三秒共享预算。这只约束结果发布顺序，不保证完整同步各数据阶段原子提交，也不撤销已发出的上游请求。


## 在线身份清单的一致性

在线成员和身份字段先在单条固定 Redis 连接上分批读取，再用只读 `MULTI/EXEC` 同时核对完整成员顺序、数量和 15 个身份字段。核对覆盖账号、地址、登录代次、产品、组、控制策略、VLAN、MAC、设备和 NAS 等关联；缺失字段与空串分别比较。观测时间取自最终事务开始时的 Redis `TIME`，不会使用分批读取开始时间或客户端完成时间。连接中断后不在新连接上继续原观测。

最终事务受配置会话上限约束，最多 100000 条；分批大小最多 2000。最终核对会短暂占用上游 Redis 的事务执行时间，不能把它视作完全无阻塞的分页查询。实现无需 `EVAL`、`EVALSHA` 或 `WATCH`，兼容现场禁用 Lua 的 Redis；不向上游业务键写入数据。身份字段或成员与已读内容不一致时，整份清单拒绝发布，接口返回 409，审计记为 `observation_conflict`，不把可重试观测冲突登记为连接故障或成功同步。

仅更新流量计数不影响身份投影，因此不会阻断同步。字段或成员先变化后恢复、且最终完整投影与候选清单一致时，可以接受最终观测；该保证针对最终观测点的身份一致性，不声称记录了中途每次变更，也不保证产品、用户组和身份三个独立阶段构成一个全局事务。

## 产品与控制策略目录的边界

产品和控制策略哈希原本就在一个只读事务中读取，保持该一致性保证。最终事务先读取 Redis `TIME`，再读取成员、关联与哈希；目录成员和预读关联变化时，整份目录拒绝发布，返回可重试的观测冲突。同步接口返回 409，仅登记 `observation_conflict` 审计，不据此把连接标为故障或登记完整同步成功。

配置的记录上限同时约束产品清单、控制清单及产品引用合并后的不同控制策略总数。产品清单或控制清单中的空成员、重复标识、首尾空白和超过 200 字节的标识，在读取哈希之前拒绝；产品对同一控制策略的重复引用仍按既有集合语义去重。每个关联清单继续受同一记录上限限制，不截断超限目录来伪造完整快照。

目录读取增加 30 秒上下文上限，并遵守调用方更短截止时间；生产接入和独立目录同步命令均启用 Redis 上下文网络超时。独立命令 `srun-policy-snapshot` 的默认端口调整为产品目录的 `16382`；使用其他部署端口时仍可显式指定 `--redis-addr`，避免默认读取在线会话实例的空目录。

整个目录的原始产品关联及策略目标/参考项合计最多 100000，控制策略参考字段合计最多 200000；每个控制策略仍最多 256 个参考字段。去重之前校验原始规模，避免大量重复引用绕过资源边界。先读取各关联清单长度，在下载前校验总量，再读取已知长度及一个变化哨兵；最终原子事务以这些长度重新核对内容。

产品哈希只读取参与目录语义的三个字段；控制策略的参考字段仍完整保留。目录专用 Redis 客户端使用 RESP2，在驱动收到分配长度之前检查响应头：单个字符串最多 1 MiB，单个完整响应最多 32 MiB，一次目录读取累计最多 64 MiB、1000000 个响应元素，数组最多 100001 个元素、嵌套最多 8 层。这些限额约束本程序的下载和分配，并不承诺上游 Redis 的内存或事务延迟上限；TLS、部署凭据和端口配置继续生效。

标准快照在构造完整 JSON 前统计转义后的字符串体积，完整规范 JSON 最多 16 MiB，与快照接入请求上限一致。超限返回 422，并仅登记 `catalog_resource_limit` 审计，不把资源拒绝登记为连接故障、成功同步或部分目录。完整同步各阶段仍分别提交；较早身份阶段的成功提交不会因后续目录失败自动回滚。

### 请求取消与连接故障

手动请求或调度器在授权库、在线 Redis、产品目录 Redis、北向接口检查或完整同步读取阶段返回 `context.Canceled` 时，记录对应 `integration.srun4k.test` / `integration.srun4k.sync` 的 `cancelled` 审计，不更新连接状态、错误详情、结果顺序或成功时间。嵌套只读检查和外层同步各自保留取消审计，操作者信息保持不变；审计使用独立的 3 秒预算，避免已取消的请求丢失记录。仍可接收响应的调用方得到 HTTP 408 和“4K操作已取消，请重试”。已断开的调用方不保证收到响应。

判定依赖错误链中的 `context.Canceled`，不按错误字符串或请求上下文已取消这一事实推断。已确认的连接拒绝和上游读取的 `context.DeadlineExceeded` 仍记录故障；取消后也不会抹掉原有故障。完整同步的已完成阶段可能已经提交，本次改动不承诺跨身份、产品目录和用户组三阶段回滚。结果与成功审计提交失败继续使用既有 HTTP 503，不将其伪装成成功或连接失败。

### 在线身份清单的响应与容量保护

在线身份读取使用与产品目录共用的 RESP2 流式响应保护模块，但容量独立设置，避免产品目录的数组上限误伤 10 万会话的身份校验。驱动收到 bulk/array 分配长度前先验证：单字符串最多 64KiB，单响应最多 128MiB，整次读取最多 256MiB；单数组最多 100003 项、单响应最多 200 万个数组元素、整次读取最多 400 万个数组元素、嵌套最多 8 层。最终 MULTI/EXEC 校验 10 万会话时包含超过 160 万个元素，仍在身份专用容量内。

只下载 15 个身份投影字段。字段值最多 4096 字节，整批投影字段名和值的原始 UTF-8 字节总和最多 64MiB；先校验这些边界，再展开 IP 地址身份记录。完整观测和最终原子校验仍使用同一固定连接，读取预算按操作重置，并保留 30 秒时限。失败时返回空观测，不发布半份身份清单。恢复数据后，同一客户端可再次读取完整清单。

超限返回 `ErrOnlineResourceLimit`，同步接口使用 HTTP 422，审计为 `online_resource_limit`，保留已有连接健康状态和成功结果。非法字段、真实超时、连接失败仍按其自身原因报告。上述限制约束客户端响应和投影容量，不约束源 Redis 的内存、事务执行时间，也不构成整个进程的 RSS 硬上限；后续身份转换及已完成阶段的提交仍遵循现有同步流程。

在线源实例标识最多 200 字节，外部/待重试清单的单行字段最多 64 项；超过配置会话数的清单同样按资源拒绝处理，不记录成连接离线。

### 在线身份摘要的分配控制

完整清单校验与地址展开共用同一条验证路径。读取后的有效性检查和 CLI 预览统计只解析地址、校验源容量与会话键，不生成随后被丢弃的地址记录 map；实际同步通过 `IdentityRecordsWithStatsContext` 一次展开同时获得摘要，完成结果直接使用该摘要。账号数按身份记录使用的 `user_name` / `username` 优先级与去空白规则去重，避免有效别名被合并成空账号。

地址顺序、IPv4 映射地址去重、登录代次会话标识、重复会话键拒绝及完整空清单语义保持一致。任何末行校验或地址展开超限失败都返回空记录和零摘要，调用方不得提交部分观测。统计优化不缓存可变源记录，也不取消实际事件转换和完整快照校验；进程 RSS 仍不受硬上限保证。

### 完整快照的标准事件转换

完整身份快照通过身份适配器的 `NormalizeRecord` 逐条生成标准事件，复用 JSONL / CSV 入口的同一映射构造函数；控制面只负责完整性、权威范围、地址和重复会话校验。转换不再为整批输入、整批输出和二次解码保留 JSON 缓冲，全部记录通过后才返回事件列表，末行失败仍返回空结果。

有效 UTF-8 记录直接映射；无效 UTF-8 使用逐条 JSON 兼容路径，保留替换字符、碰撞字段的顺序和既有事件 ID。采用与旧 JSONL 扫描器一致的单条 JSON 长度边界，计入 HTML、控制字符、无效 UTF-8 以及 U+2028 / U+2029 转义；编码后的单条记录必须小于 16MiB。非有限的最终置信度仍拒绝，既有输入置信度的范围归一化规则继续生效。独立的 JSONL / CSV `Convert` 入口维持原有读写和统计行为。

这项优化减少临时分配，不给完整同步设定进程 RSS 硬上限。源清单、最终事件列表、既有快照 ID 的 JSON 摘要计算以及分阶段提交仍保留；验收中的内存限制只施加于临时测试作用域。

### 本地身份处理的取消边界

在线投影校验、地址记录展开、快照 ID 计算和标准事件转换检查调用方上下文；展开与转换在每条记录之间、复制大字段集合时也定期检查。已取消或已到期的处理不继续跑完整批次，返回空记录/零摘要、空 ID 或空事件列表。兼容的无上下文统计与准备入口使用后台上下文；实际同步和快照 HTTP 接口传递各自请求上下文。单条标准映射与 JSON 字符串编码仍是同步操作，检查粒度不构成逐指令抢占或整个进程的内存硬上限。

快照 ID 按原有 JSON 字节序列流式计算，每次仅编码一条记录，保留字段顺序、空数组与 null 的区别、时间格式、HTML/无效 UTF-8 转义及原有摘要。相同合法观测的 ID 不变，时间或身份范围变化仍产生新 ID；时间无法编码时返回真实错误，不再对空缓冲产生固定摘要。

身份快照 HTTP 接口的既有十秒处理预算从请求解析前开始，涵盖本地准备；准备取消或超时返回 HTTP 408，不进入快照存储。分块提交使用其既有请求上下文准备完整批次。4K 本地处理的超时使用独立错误类别，返回 HTTP 408 并以 `local_processing_timeout` 记录审计，保留连接状态、错误、结果顺序和成功时间；真实上游读取超时仍按原有故障逻辑处理。取消仍采用 `cancelled`，操作者及三秒独立审计预算保持一致。此前已完成的同步阶段不因此回滚。

### 身份来源授权与历史重放

身份授权按来源、传感器、校区和接入域四项完整匹配。4K 动态注册只覆盖其原生观测声明的空校区和空接入域；需要其他范围时必须显式注册，不能借用同一来源和传感器的动态授权。策略身份查询遵守相同范围约束。

快照、事件批次和历史重放在请求上下文内查询来源配置。取消或超时返回 HTTP 408，不向身份存储提交；来源配置查询故障返回 HTTP 503，响应不包含底层数据库错误。未注册或范围不匹配继续返回 HTTP 403。一次事件批次对同一完整范围只查询一次，缓存只存在于本次请求，下一批次重新读取授权和同步间隔。

历史批次重放重新检查当前来源注册，并将当前权威间隔用于提交的标准事件；来源被移除或批次混入未授权范围时，整批拒绝，不修改原有批次状态及保留的标准事件。成功重放保留事件 ID，原始留存事件仍保留当时内容。来源配置查询与身份提交并非同一数据库事务，本机制不承诺配置在并发修改期间的事务隔离。

策略身份读取和来源状态读取使用相同的完整范围授权解析器。动态或托管来源配置查询失败时返回不可用错误，内部仍可追溯原始原因，外部错误文本不含数据库或驱动细节；不把查询故障伪装成正常的未注册会话。调用方在取消或超时后不会得到可用于决策的部分身份清单，审批预览和执行前校验沿用读取错误分支停止处理。静态注册优先于同范围动态注册，托管来源健康与新鲜度仍按原有规则覆盖结果。

校区或接入域筛选使用独立结果切片，不改写身份读取器提供的会话清单。策略和状态查询的授权缓存仅作用于本次读取，不跨请求保留；没有配置登记与身份提交的跨阶段事务隔离保证。

### 动作投递前校验的时间边界

通用 PostgreSQL 投递与原生最终授权传递其当前上下文；事件通道、身份、当前策略、证据和例外读取共享最多五秒的校验预算，调用方更短的截止时间优先。取消或超时不返回允许结论，保留错误链中的原因。事件通道的兼容布尔入口也具有五秒上限；未就绪与读取故障分别处理，读取故障对外只提供安全错误文本。

原生最终授权从当前 SQL 记录读取动作、连接器和全局紧急停止状态，不打开旧的全局操作事务；独立读取仍不构成同一事务快照。内存或已加载的读取视图等待本地文档锁时响应上下文取消。风险校验沿用同一上下文，成功返回前再次检查；原生意图绑定的身份展开也采用上下文入口。

本项约束的是投递前校验，不替代控制器请求预算、持久化意图日志、撤销审计或未知结果的后续对账。动作状态提交和网络操作仍是独立阶段，不承诺取消已发出的请求能撤销远端动作。

投递前失败结果只更新仍处于校验时阶段、执行意图和尝试状态仍匹配的动作。较新的成功回执、撤销、取消、失败结果或已变更的账户、证据、重试、远端回执信息均不被旧校验覆盖。PostgreSQL 更新在现有目标行事务内完成；内存路径在同一文档锁内检查并更新。比较按 PostgreSQL 微秒时间精度归一化更新时间、到期、冷却和下一次尝试时间。更新时间保留为尝试版本，防止旧超时消耗新一次人工重试的预算；创建时间及历史错误文本不作为执行意图。

内存投递在切换为运行状态前，也比较校验快照和当前完整动作，拒绝投递已经变更的载荷。原生 SafeDisable 最终校验明确阻止发送时，使用上述受保护的失败更新，保留已经生效的人工取消，不把防发送结果当成远端失败回执。

### 迟到回执与动作状态

通用 HTTP 完成回执、传输重试以及原生通知、SafeDisable 的结果写入，核对投递时的完整动作快照。SQL 动作保存返回数据库实际写入的更新时间，投递在提交后使用该版本的快照；比较保留更新时间、重试计数、账户、证据和回执字段，并将时间归一化到 PostgreSQL 微秒精度。恢复调度后的新运行轮次不能被旧响应完成，也不因旧失败额外消耗重试次数。HTTP 请求和响应仍留存在实际尝试记录中；状态冲突另记录 `enforcement.delivery_receipt` 审计，不覆盖已经完成的恢复、人工停止或其他新结果。

签名回调只有在状态允许且当前动作未并发改变时更新结果。完全重复的终态回调返回 HTTP 200，不修改动作版本、父动作或连接器熔断计数；与成功、恢复、到期、停止或影子状态冲突的回调，以及终态中不同的远端回执 ID，返回 HTTP 409 `action_receipt_conflict` 并记录冲突审计。签名确认的成功或恢复回调仍可纠正失败状态，因为传输重试耗尽不能证明远端没有执行。

这些约束保护本地结果的顺序，不撤销已发送的远端请求。原生停止状态仍保留“已发出的请求无法撤回”的说明，实际执行情况需要查询原生意图日志、回执和在线会话；SafeDisable 模拟器验证不等同于现场账户禁用与恢复验收。

原生会话断开在绑定持久化意图前、最终发送授权及保存对账结果时，也核对当前完整动作与已提交的投递快照。保持“运行中”但已更新版本、账户、证据、租约、持续时间或重试计数的动作，不能被旧线程绑定、授权或完成。绑定冲突与结果冲突分别记录 `enforcement.delivery_receipt` 的 `receipt_conflict:native_binding` / `receipt_conflict:native_observed`，保留较新动作原记录。已提交的不可重复发送预约和真实观察继续保存在原生意图日志中；冲突不生成新命令，也不记为当前动作的 `enforcement.native_observed` 完成审计。成功应用的观察审计使用独立三秒预算，避免执行上下文到期直接丢失该审计。

通用 HTTP 的实际尝试记录使用独立三秒数据库写入预算，不继承可能已经到期的八秒 HTTP 请求上下文。尝试表锁等待或写入错误不改变远端完成回执，也不额外增加传输重试或连接器熔断计数；真实传输失败仍按原结果排期。先处理动作结果，再以独立三秒预算写 `enforcement.delivery_attempt` 审计，结果仅包含 `attempt_storage_timeout` 或 `attempt_storage_failed`，不暴露数据库错误、连接信息或远端响应。审计也失败时记录安全的服务日志。该流程不保证数据库故障期间尝试记录与回执原子落库；缺失记录不自动补发远端请求。

### 临时校验故障与恢复重试

投递前的上下文取消、超时、带类型的配置读取故障和身份来源授权查询故障，使用独立的 `precheck_retry_count` 和 `precheck_retryable` 记录。成功持久化的前四次临时故障依次排期 15、30、60、120 秒，连续第五次进入阻塞，停止自动重试；这些故障不增加传输 `retry_count`、不创建远端尝试记录、不增加连接器熔断计数。明确的授权拒绝、证据失效、事件通道未验证或能力缺失仍停止投递，不通过错误文本猜测故障类别。

调度器和投递入口都检查下一次尝试时间，重复队列唤醒不能缩短临时校验退避或通用传输退避。已有原生意图的重启对账沿用原有行为，由不可重复的发送预约保证不重发命令；出现临时校验故障时仍遵守该故障的退避。重启从数据库恢复原排期和计数；再次投递重新执行全部现有证据、身份、审批、连接器和紧急停止校验。校验通过时清除临时故障标记，真实门禁变化保留明确阻塞原因。排期、拒绝或耗尽记录 `enforcement.precheck_retry` / `enforcement.precheck_blocked` 审计，写入动作状态后释放锁，再以独立三秒预算写审计。

操作者再次撤销一个已成功且仍有效的父动作时，可以重试其阻塞的恢复子动作。账户、会话、校区、接入域、证据、策略参数、租约和幂等键必须继续匹配原父动作；恢复使用原子动作 ID 和幂等键，重置本地校验预算，保留传输计数，记录 `enforcement.revoke.retry` 和操作者。重复撤销请求返回已有待投递、运行或完成记录，不生成第二个恢复动作。人工重试也重新检查当前门禁，不绕过紧急停止或影子模式。

通用 HTTP 恢复动作耗尽三次传输失败后，操作者再次撤销原父动作可以重新排期原恢复子动作，继续使用同一动作 ID、幂等键、租约与证据范围。累计传输失败计数不清零，实际尝试记录继续编号；成功回执恢复父动作，再次传输失败则立即回到失败状态，不获得新的自动退避预算。排期和运行期间的重复请求返回已有动作，不新增恢复意图或重复写人工重试审计。新的人工请求记录 `enforcement.revoke.retry` 和当前操作者；重启后也保留累计计数与原恢复意图。正常调度仍通过同一幂等键处理崩溃后的不确定结果，不能保证已经发送的 HTTP 请求在崩溃期间只出现一次。

原生 4K 定时禁用仍由控制器 `disable_time` 到期恢复，不生成没有 SDK 支持的提前恢复命令；已确认恢复、已撤销的父动作、存在远端回执、范围已变更或未耗尽传输预算的其他失败子动作不按本机制重新排期。模拟控制器的恢复结果不作为现场账户验收。


## 在线清单与认证事件的进度

接口分别返回 `last_identity_poll_at`（完整在线清单最近检查）和 `last_identity_event_at`（最近收到的真实认证事件），弹窗只在时间存在时显示对应行。清单成员不变也更新检查时间，不重复追加相同快照。上线、下线事件通道等待接入或缺少近期事件时，继续每分钟检查清单；清单同步不能把事件通道标为正常。

认证发送端使用现有 `POST /api/v1/integrations/identity/events`，携带配置中的 Bearer 令牌、`Idempotency-Key`、注册的 `source` 和 `sensor_id`。标准记录包含账号、IP、会话 ID、时间、`entity_role=endpoint` 与 `action=start/interim/stop`；双栈地址分别提交，会话 ID 包含来源与登录代次。不要发送编造的 MAC、终端 ID、校区或接入范围。当前接口仍校验来源授权，失败批次可幂等重试。

只有成功持久化、包含账号与会话、时间处于最近两分钟内的真实会计事件才能标记事件通道正常；清单 reconcile、迟到历史事件和超前超过一秒的事件不更新正常状态。超过两分钟缺少新事件时恢复清单兜底，需发送端提供真实的周期会计更新以维持事件进度。实际处置仍受原有身份新鲜度、登录代次、影子验收、策略和冷却条件约束。190 当前只有清单接入，真实发送端配置需在认证系统启用对应会计输出后验收。
