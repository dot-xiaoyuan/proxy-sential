# 内网扫描识别首期实现

检测只消费标准事件的 `flow` 类型，以传感器、校区、源 IP、连接 ID 去重；连接 ID 缺失时以事件 ID 作为单条连接记录。Zeek `S0`、`REJ` 计为明确失败，`SF`、`S1` 及明确建立/关闭状态计为成功，其余计为结果不明。已知结果不足 80% 时不生成扫描发现。DNS、TLS、HTTP 等协议事件不参与探测计数。

目标网段取已启用的 `network_zones.cidrs`，重叠网段按最长前缀匹配。`internal_scan_rules` 按校区配置，默认没有启用规则；`excluded_source_cidrs` 用于经确认的授权扫描器、监控和基础设施来源。连续扫描的初始条件为 5 分钟内单一网段至少 32 个不同目标、50 次连接尝试、16 个连续地址及 60% 明确失败；跨网段稀疏扫描的初始条件为 10 分钟内至少 50 个网段、80% 网段各不超过 2 个目标、最多 3 种端口及 50% 明确失败。阈值是回放起点，不能视为现场准确率承诺。

每分钟后台读取最近 10 分钟最多 20 万条连接事件；超过上限则整轮标记 `incomplete`，不写发现。已启用校区没有网段时同样标记不完整。`internal_scan_runs` 保存每轮状态，`internal_scan_findings` 保存结构化结果和原始事件 ID 摘要，二者保留 7 天；证据另按现有证据生命周期管理。新增结果只写现有证据链，不设扫描评估、标注看板或接口，不触发通知或处罚。账号归属未达到事件时点可核对条件时保持为空。

启用前须只读核对流量覆盖率、连接状态覆盖率和校区网段配置，并用正常业务、授权扫描及两类扫描回放调整阈值。184 在 2026-10-23 的只读核对中，最近 7 天 `flow` 事件为 0；`network_zones` 共 5 条启用记录，其中仅 1 条配置 CIDR。因此当前无法用现场流量验收此算法，规则须保持关闭。普通代码发布不等于规则启用或现场验收。

规则由受控的数据库配置流程维护，不提供扫描评估接口。例如完成上述核对后，为已确认的校区写入一条 `internal_scan_rules`，逐项填写排除来源与阈值，并将 `enabled` 设为 `true`；回滚时设为 `false`。不得在只有一个已配置网段的现场启用“50 网段”检测并解释其无命中为安全结论。
