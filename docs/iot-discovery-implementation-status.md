## 本轮修正

1. 批次领取使用有界工作队列索引和账本主键点查。现场 `EXPLAIN` 从扫描约 7.8 万条账本、排序后领取，变为 `discovery_batch_pending` 与 `ingest_batches_pkey` 的嵌套索引访问。
2. 每次归档和投影限制 50 条。归档键包含原始批次 ID 与偏移，故障重试复用相同键；原批次账本和首次计时不变。之前已核验整批归档的任务保留原确认。
3. 发现专用一年证据归档仍然保留。普通标准事件库的保留期不能替代该归档；没有发布跳过归档的临时方案。
4. 原未完成任务移到 `backfill` 通道，保留原始事件、偏移、错误和时间。新鲜度仍包含所有通道的未完成缺口，不把迁移通道当作任务完成。
5. 新鲜度入库/处理水位使用单行增量结果，列表不再聚合全部已完成任务。未完成时间、失败、结果版本读取专用索引。
6. 通用文件入库只接收配置中由 Zeek 负责的发现协议，旧 `device-signals` 不因协议同名而重复进入发现队列。
7. 前端独立读取类型统计，展示统计时间和处理中状态；统计错误独立显示，不用零数量替代。
8. 采集失败退出码改为非零，修复队列满后退出 0、`Restart=on-failure` 不拉起的问题。discovery6 现场已验证自动重启。

9. 现场确认 `database_22P05` 来自协议文本中的 NUL：抽样 100 个暂存文件有 4 个包含转义 NUL。异常批次使用 `base64-json-v1` JSONB 封装无损保留原文，普通批次兼容原数组格式；不适合状态投影的记录留拒绝回执，同批其他记录继续。8 MiB 上限按未封装原文检查，异常封装最多增加约三分之一存储。证据仍归档一年，处理失败不清理。
10. 已排队的捕获小窗口合并后持久化，减少每个文件的 fsync/目录同步，不增加固定等待。最多 2000 条/8 MiB，事件顺序和原始 JSON 保留；回放覆盖顺序、边界和磁盘失败。
11. 共享入库水位移至设备处理之后，已确认批次的后续片段不重复改写账本水位。历史回填增加有界参数，184 实际启用 1 路、每轮 1000 ms，避免仅限制应用进程却放任数据库执行并发 SQL。
12. 现场死锁日志明确指向 `discovery_protocol_runtime`：捕获统计按配置顺序更新、投影按 Go map 随机顺序更新。修复统一协议顺序并将协议计数置于状态处理之后；新增两个投影消费者与捕获统计的并发数据库回放。discovery10 已完成标准发布与进程核验，Go、race 与隔离并发回放通过；14:54 与 14:57 对照数据库死锁累计值均为 20，短观察窗口内没有新增。不能代替持续并发验收。

## 新辅助结构成本

| 结构 | 读取收益 | 写入成本 | 保留与失效 |
|---|---|---|---|
| `discovery_pipeline_watermark` | 列表两次点查获取已确认入库与已处理水位，避免随历史批次数扫描 | 入库确认/批次完成事务更新一行；存在锁串行成本，须继续做持续写入测试 | 始终一行；与事务一起提交，不使用过期缓存；不替代待处理缺口 |
| `discovery_batch_pending_error` | 最老失败任务按索引取一条 | 仅失败且未完成的任务进入索引 | 完成后自动离开部分索引；原错误不被伪装为成功 |
| 分段归档 | 控制单次 ClickHouse 写入及核验规模 | 每 50 条增加一个分段核验；保留按首次入库时间计算的一年证据 | 稳定段 ID 支持重试核验；未核验不清理唯一副本 |

本轮仅完成隔离功能/故障回放和现场实际规模查询测试。上述结构的 1/3/10 倍增长、24 小时持续写入与磁盘容量验收未完成，不能作容量承诺。
