# IP 与楼宇关联：全链路范围与改造边界

日期：2026-10-13。状态：代码梳理与建议方案，尚未实现本方案，不代表现场已关联。

本次只整理关联范围、接口约定和实施边界，不修改正在进行的设备中心存储查询实现，不自动授权部署。现有工作区有其他线程的未提交实现；下列路径表示核对到的代码入口，不代表这些改动均已上线。现场此前核对到的 identity-ui2 版本保留了楼宇网段配置，但尚无统一的按 IP 自动归属链路。

## 1. 结论与现有基础

可以实现。全站涉及业务 IP 的展示范围较广，但基础能力可以共用，不需要每张业务表重复增加一套楼宇字段，也不需要重写采集、风险评分或处置动作。

现有 campuses、buildings、network_zones 已支持校区、楼宇和 CIDR；account_sessions、identity_access_history、risk_cases 及 ClickHouse normalized_events 已有部分楼宇字段。然而这些字段主要接收上游携带的值，不等于系统已经消费配置中的网段并自动归属。设备和会话不能因历史 IP 命中而被标为当前位于某栋楼。

应分清三种不同能力：

1. 展示关联：给已分页返回的 IP 增加按指定版本配置匹配的位置说明。
2. 查询关联：按楼宇筛选、游标分页、排序和统计，必须在分页前的结果/检索层完成。
3. 历史归属：按事件发生时适用的配置与作用域解释位置，并为案件和执行记录保留当时的依据。

第一种是中等规模的横向功能；三种全部实现是中大型跨模块改造。只做展示关联，不能声称已支持楼宇筛选或可靠的历史归属。

接口族是改造清单，不是要求每个返回体都新增字段。实施时需逐个核对实际结构、权限、分页和 IP 角色。前端入口分散在二十多个页面及组件，不宜当作单页小修估算。

## 3. 统一归属规则

- 输入至少包括 IP、校区/传感器/网络域作用域、IP 角色及必要的观测时间。私网地址可能跨域复用，单独一个 IP 不一定足够。
- 先限定作用域，再做 CIDR 最长前缀匹配；同一优先级配置指向不同楼宇时返回冲突。作用域不足、来源冲突不能任意选择结果。
- VLAN、SSID、接入点只作可选辅助信息，不是按 IP 归属的前置条件；现场以网段配置为主。
- 结果应表达“该地址按某配置归属某楼宇”，而非 GPS 式物理位置保证。NAT、VPN、跨楼共用网段等情况保留适用范围说明。
- 对不匹配的地址不展示楼宇占位；冲突、服务错误、处理中和结果过期必须与无匹配区分。
- 不把源 IP 固定当成用户端。按流量方向、主体地址及采集范围识别角色；管理 IP、NAS IP 仅表示对应基础设施的位置。
- 记录时间早于配置生效时间且无可验证历史依据时，仅可显示“按当前配置匹配”。不能把新配行政楼网段追认成过去所有记录的确定位置。

## 4. 建议的共用结果约定

统一结果建议携带：campus_id/name、building_id/name、network_zone_id/name、matched_cidr、mapping_version、match_basis、status，以及适用的 matched_at/valid_from/valid_to。status 需要区分 matched、unmatched、ambiguous、pending、error、stale；原始上游楼宇证据和配置匹配结果分别保留，避免覆盖。

当前归属和历史归属使用同一类型，但明确依据是 current_configuration、event_time_configuration 或 source_reported。时间窗口聚合若跨多个配置版本，不能只取窗口结束时版本冒充整个窗口归属。

每个源/目的/主体地址各有位置结果；设备具有多地址时按地址保存结果，只有全部有效证据支持同一楼宇时才生成设备级摘要。

前端统一 IP 展示组件负责链接、复制、楼宇辅助文字和匹配依据展开；多个页面不自行下载组织全量数据后逐行匹配，不对每个 IP 发一次请求。楼宇展示失败不能阻断原始记录展示，但必须有真实失败提示。

## 5. 全链路实施方式及与存储线程的边界

推荐链路：

配置保存与版本发布 → 统一前缀匹配器 → 当前关系/记录的位置结果 → 分页接口 → 共用 IP 组件 → 报告、导出与通知。

### 展示关联可以先独立完成

- 统一匹配器使用按作用域与版本组织的内存前缀索引，读取配置变更时原子替换快照。
- 普通已分页明细可在接口响应组装时，对本页去重 IP 做有界批量匹配；无需加载业务历史或请求内重建全网状态，不产生逐 IP 数据库查询。
- 单次响应采用同一个配置版本。跨进程快照更新和重启重载需要有明确机制；不能只靠本进程保存时刷新，否则其他进程会长期显示旧配置。
- 这一方式只提供当前配置说明；未经版本化依据支持，不宣称历史位置准确，也不能据此在前端进行楼宇过滤。

### 设备中心与存储改造只约定接点

另一个线程继续负责事件消费、有效地址语义、设备当前状态、检索索引、游标、冷热历史与容量。楼宇功能提供匹配器和统一结果约定，由其稳定的增量更新接口接入；避免同时修改同一批未完成迁移、投影表和任务实现。

双方需要先约定：

1. 可供定位的有效地址、作用域、时间及关系版本。
2. 归属结果挂在地址关系还是设备摘要，以及多地址和冲突返回方式。
3. 地址新增、换绑、释放、自然过期、更正、撤销如何触发位置更新。
4. 楼宇配置发布如何仅刷新受影响地址/设备；删除、停用、缩小网段及优先级改变也要失效。
5. 楼宇筛选对应的结构化结果字段/关联索引、分页和统计口径、缓存版本以及变更进度。
6. 案件/处置的位置快照与原始事件保留规则如何衔接。

不创建第二套设备投影或独立消息队列。新事件的位置处理不得突破设备中心首次入库后5秒可查询目标；配置变更全量影响的收敛时间另行测量并显示进度，不能暗中沿用同一5秒承诺或假报完成。

### 历史和统计后续接入

- 从配置版本化开始保留历史匹配依据，案件与动作记录固化必要的名称、CIDR和版本；后续改名也不会改写原始执行上下文。
- 没有可靠历史配置时，可按当前配置做辅助标注，不为“历史准确”伪造回填。
- 按楼宇筛选要在分页前执行，不能只过滤已返回的一页；按楼宇统计不能遍历所有页面临时求和。
- 常用当前筛选走现有结果库的结构化结果/检索索引；大范围事件历史过滤和聚合走既有ClickHouse查询设计。具体物理表由存储设计统一决定。
- 不立即对海量事件做全量UPDATE或重写；是否需要历史物化由查询需求、时间语义和隔离容量测试共同决定。

## 6. 改造量与建议分期

| 范围 | 工作量判断 | 主因 |
|---|---|---|
| 只给一个页面的 IP 显示当前配置楼宇 | 小 | 单点展示，但不能覆盖全链路 |
| 全站业务 IP 一致展示当前配置楼宇及依据 | 中 | 共用匹配器、结果类型、API与多页面接入、缓存失效、权限和回归 |
| 增加设备/会话楼宇筛选和汇总 | 中至大 | 接入增量结果和检索索引，涉及分页、统计、一致性和性能 |
| 历史准确归属、案件快照、处置通知、导出全部贯通 | 中大型 | 时间版本、历史证据保护、多种IP角色、跨模块完整验收 |

建议第一批完成统一匹配器与展示合同，覆盖IP详情、设备/会话详情、风险列表与详情。第二批扩大到事件/DPI、发现、共享设备及其他明细，同时与存储线程接入当前归属筛选。第三批完善历史快照、统计、导出和通知。物理存储和迁移尚在变化，不宜承诺精确人日；稳定接口后按模块估时更可靠。

## 7. 验收重点

- IPv4 / IPv6、多网段、同IP不同作用域、重叠前缀、冲突、停用和配置版本切换。
- 多地址设备、会话换绑、地址释放、自然过期、乱序、晚到及更正/撤销，当前与历史不得混淆。
- 同一IP在不同页面显示同一版本下的一致结果；列表、详情、导出、通知对同一记录使用一致口径。
- 分页先筛选后切页、统计独立，匹配失败不伪装无记录，旧版本结果标明过期。
- 前端三视口截图、DOM探针、缺省信息规则与对比度；相关Go/前端测试、类型检查和生产构建。
- 普通梳理文档不执行容量压测；涉及设备中心实现时按现有存储设计完成隔离回放、故障恢复、1/3/10倍及20路查询验收，10倍组合负载持续24小时。测量楼宇索引和匹配的额外读取/写入/内存成本，不在184现场造数。
