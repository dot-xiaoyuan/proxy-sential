# IP 详情接入新流观测（2026-10-26）

## 问题与改动

`10.157.2.191` 的握手和 TTL 标准事件已经进入新流检索；旧 IP 设备识别摘要仍从 `device_inventory_current` 读取。重复的 handshake/MAC 信号合并为一条事实，不能用这一行的数量判断是否持续采集。

新增 `GET /api/v1/ips/{ip}/traffic-observations`，在 IP 详情的“终端识别”页签下展示独立的“IP 流量观察”。旧摘要和每条设备信号显示实际最后观测时间；信号累计次数明确区别于报文数、设备数。握手正文中的 SNI、Host、UA 和 TTL 观测不直接变成设备身份或路由器类型结论。

## 查询边界

- 使用 `events:read` 权限。服务器固定配置的 sensor 作为作用域；额外 sensor 参数与本站不一致时拒绝。
- 在已有 `stream_shared_source_cutovers` / `stream_source_cutovers` 中读取当前来源代次、捕获域、切换时间和登记状态；不扫描事件发现作用域。
- ClickHouse 复用 `stream_event_search`，按捕获域、精确 subject IP、sensor、代次前缀和 handshake/ttl/hop_limit 协议筛选。时间范围最多 15 分钟，每页最多 100 条；前端默认 20 条。游标绑定 IP、代次及所有筛选，来源切换后旧游标失效。
- 查询使用 1 个线程、5 秒执行上限、128 MiB 内存、100 万读取行和 128 MiB 读取字节预算；超限返回 503，不截断成成功结果。ClickHouse 读取限制按数据块核算，不能理解成逐行精确资源计费。
- 列表仅取窄索引，正文在展开时通过已有稳定引用接口读取和校验。不新增表、索引、缓存、迁移、写入支路或消费者。
- 返回 `ready`、`source_unavailable`、`before_cutover`，失败使用 HTTP 错误；来源暂停或关闭单独展示。查询完成时间与事件观测时间分开，页面手动刷新；不把来源登记 active 或空列表当作采集完整性的证明。
- 当前代次以切换时间裁剪范围；更早及被审计取消的历史不混入当前结果。不恢复旧投影双写、不回填历史。
