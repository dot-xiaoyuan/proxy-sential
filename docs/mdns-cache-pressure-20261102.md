# mDNS 缓存满额准入审查（2026-11-02）

r39 的 20 分钟现场观察中，缓存从 2,643 增至 5,794 条；10,000 条和 8 MiB 限额均未触发拒留。新键在满额时仍会被拒绝，当前报文照常解析和记录，但后续跨报文关联可能缺少缓存依赖。

本地满额回放显示：暂时没有 SRV 指向的有效 A，仍可与晚到的同作用域 SRV 关联。多个服务也可共用目标主机。因此“当前没有 SRV 引用”不能证明 A/AAAA 可安全驱逐；本次不改变准入和回收语义。

新增 `retained_by_kind`，按 A、AAAA、PTR、SRV、TXT 记录当前缓存占用，与已有按类型拆分的拒留累计数一同判断容量压力。计数在准入、撤销和过期时更新，快照不扫描缓存；它不代表漏发现设备数。需等现场出现实际限额压力并核对报文分布，再设计有界替换及回退。相关 Go 测试、构建和 vet 通过；未在 184 造数或修改现场。

## 11 月 2 日满额后的容量调整候选

04:25–04:40 UTC 的下一轮真实采集在 10,000 条上限达到满额，内容预算仅占用 3.49 MiB/8 MiB。累计拒留 72,680 次，其中 SRV 15,402、TXT 24,196、A 7,672、PTR 25,410；这些是尝试次数，不等于不同设备或最终漏发现数。跨报文的 SRV、TXT 和地址关联依赖缓存，满额回放已证明可能漏掉服务关联。

候选将记录上限调为 100,000 条、内容预算调为 64 MiB；原先 10,000 条加上本轮全部拒留尝试，即使每次都是新键，也只有 82,680 条。服务器只读检查显示当时可用内存约 26 GiB，发现进程 RSS 约 263 MiB。新限额保留到期清理、TTL 0 撤销、作用域隔离和单条内容预算，不做无证据的驱逐。到期堆和关联索引仍按键访问，实际 RSS、CPU、拒留数及服务关联收益需在减轻投影积压后观察；更长时间或不同流量下仍可能满额，不能把上调说成已补齐设备类型。

本地 M4 解码基准中，普通 A 报文在 10,000 条与 100,000 条缓存下分别约 6.64/6.70 微秒，服务目标地址报文约 7.55/7.63 微秒；现有满额、跨报文关联、过期和撤销回放通过。基准未覆盖现场 RSS 与持续输入负载，不作为容量验收。
