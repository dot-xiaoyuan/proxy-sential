# 网络设备发现

发现数据使用独立标准事件 `type=discovery`，不创建风险终端身份，不刷新流量 last_seen。发现列表入口位于终端画像右上角。

## 启用

1. 部署包包含 `discovery-worker` 和 `proxy-sentinel-discovery.service`。worker 读取现有 runtime.env 的 PostgreSQL、ClickHouse 和凭据主密钥，节点标识使用 PROXY_SENTINEL_SENSOR_ID。禁止将主密钥写入命令参数或日志。
2. 页面“基础设施接入”填写管理 IP、只读 SNMP、节点、站点和二层网络范围。SNMPv3 使用 SHA-256/AES authPriv；v2c 必须显式选择。默认 300 秒，默认不启用定时。口令留空可保留已有凭据。
3. “测试并采集”生成不可变配置快照，任务页查看各 MIB 表记录数、错误及部分完成状态。无记录不表示设备离线，也不证明 MIB 不支持。
4. 被动采集需在 worker 启动参数指定 `--interface`、`--site`、`--domain`；默认不采集。Linux 原始套接字需要 CAP_NET_RAW。仅在已核实镜像范围时配置；支持单／双 VLAN 标签，当前不解析 IPv6 扩展头或分片报文。事件先写本地 spool，再异步落库；队列满时显式停止并报错。DNS-SD 地址／服务关联缓存上限 10000，重启后等待新的公告恢复。
5. 标准事件的被动发现读模型由 recognition materializer 异步维护。必须在 `runtime.env` 配置 `PROXY_SENTINEL_DISCOVERY_CIDRS`，以逗号分隔现场 IPv4/IPv6 网段；全局地址不命中范围时直接跳过，IPv6 链路本地地址按传感器和采集接口隔离。首次启动从当前时刻消费新事件，不回放历史 ClickHouse 数据。
6. 主动发现先明确允许 CIDR、排除 CIDR、协议、采集接口及显式 IPv6 地址，预览后保存。手动试扫完成当前配置版本后才可启用每日定时；修改配置自动关闭定时并请求停止旧任务。每节点最多一个扫描、16 个目标并发、全任务每秒 10 请求、2 秒请求超时、一次重试、最多 4096 个目标。ARP/ND 使用 arping/ndisc6，ICMP 使用 ping，worker 执行前检查依赖；ARP/ND 仅允许指定接口直连网段。
7. SSDP/ONVIF 首期为目标定向 UDP 发现，不发送全网广播。部分设备仅响应组播，因此可能漏检；无响应不证明离线。IPP 为 Get-Printer-Attributes，只读；IPPS 使用系统信任链，不忽略证书错误。XML 拒绝 DTD，HTTP 禁止重定向与代理。

## 归属与证据

MAC 表的端口一律先显示路径线索，不能据此确认直连。FDB ID 经 VLAN 映射表解析，多个 VLAN 共享 FDB 时留空 VLAN。

管理员可为 SNMP 源填写身份采集器、校区、VLAN、VRF 映射。只有当前版本范围一致、非随机 MAC 与唯一有效 DHCP 租约匹配时关联已有终端。无映射或冲突时留在独立发现区。关联不写回 DHCP，后续换绑使旧关联失效。未有可靠范围映射的被动／主动 IP 记录不强行匹配终端。

服务公告生成能力，不直接确认硬件；mDNS 的 IPP／打印服务和明确型号组合时可自动标记打印机，否则只展示打印能力。LLDP、SSDP、WS-Discovery 的类型属于自报线索。查询报文、普通互联网流量、广播／组播／未指定地址不生成设备结论。原始标准事件和来源可追溯，规则版本为 discovery-2026.09.21.1。证据保留 30 天，结束任务保留 90 天；审计沿用项目审计机制。

## 运行与回滚

独立 worker 不配置源、接口和扫描范围时不发起设备探测。停用 systemd worker 可停止所有采集；各 SNMP 源和扫描配置可分别关闭定时。关闭定时不等同取消正在执行的任务，使用任务页“停止”取消。

回滚应用前先停止发现 worker，再切换旧发布目录并重启原服务。058 为增量表，回滚不删除发现证据；旧程序忽略这些表。

## 验证与现场边界

自动测试覆盖作用域、TTL／撤回、DNS 查询反例、mDNS 无地址响应、FDB/VLAN 映射、扫描范围、敏感网段协议限制、描述地址边界、XML、任务去重、租约恢复、停止、PostgreSQL 持久化、ClickHouse 重复事件归档，以及三视口页面检查。

当前没有现场交换机型号、SNMP 只读凭据、已确认的二层范围和允许扫描网段。现场 SNMP 兼容、打印机／摄像头真实性、mDNS/SSDP/LLDP 镜像可见性、识别准确率与漏检率均待验收；不得将自动回放通过解释为现场发现全量设备。

## 2026-10-23 发现积压恢复实现

本节对应新增迁移 `170_discovery_recovery_runtime.sql`。代码验证与现场恢复是独立门槛；未完成真实数据库验证与现场观察时，不表示积压已恢复。按用户 2026-10-23 的要求，本次计划取消固定倍数压测及其绑定的 24 小时、20 路查询前置条件，授权更新 184 并以真实负载观察效果。

### 运行与观测

- `discovery-worker --mode=all|consume-only|passive --realtime-workers=1|2`；默认 all / 2 保持原行为。环境变量为 `PROXY_SENTINEL_DISCOVERY_MODE` 和 `PROXY_SENTINEL_DISCOVERY_REALTIME_WORKERS`。consume-only 不抓包、不执行主动任务、不运行富化、不生成新的历史回填；passive 恢复已有被动采集，仍不运行主动任务和富化。
- 三个连接池分别限制实时（8）、回填（2）、观测（2）连接。实时每段仍为 50 条、4 秒预算；回填单路、每 2 秒最多一段、3 秒预算。实时队列超过 5 秒时停止新增回填领取，明确显示 `pause_reason=realtime_overdue`。
- 领取使用 30 秒持久租约；归档在事务外进行。结果、事件回执和分段偏移在短事务内提交，并检查租约令牌、原偏移与有效期。旧版本回退前必须停止新消费者，不能同时运行采用不同领取协议的版本。
- coverage 响应增加 `pipeline`：按 lane 返回积压、剩余事件、分段进度、处理速率、重试、超时、阶段耗时及暂停原因；`consumers` 单列 DHCP 消费者心跳，未测量的 DHCP 上游消息量不伪造为零。
- `/readyz` 的 `discovery_pipeline` 为非强制依赖；业务发现中断不会让认证与控制面整体不可用。其状态和 `/metrics` 指标必须单独检查，HTTP 200 不能代替消费验收。接口只读取状态结果；查询失败返回不可用状态。

### 重试与计时

标准事件写入通过持久的 `(sensor, source, event, revision)` 回执保护。跨批次写入按相同顺序获取会话锁，避免并发写同一修订；锁不持有数据库事务。历史已处理回执可作为已有归档确认依据。同修订内容冲突会保留任务并停止新领取；自动重启也会先检查该阻塞。

对未确认写入，先检查上次 ClickHouse query ID 是否仍执行，再按 sensor、subject IP、事件时间和事件 ID 查询实际行并校验完整内容。结果不确定且数据尚未可见时，至少等待 30 秒再尝试写入；不能仅依赖 100 块插入去重窗口。普通 ingest 写入语义不变。

`discovery_normalized_receipts.confirmed_at` 记录首次可确认的存储时间。中断前确认时间无法还原时使用原批次接收时间保守计时，标记 `confirmation_uncertain`；重试不重置。投影事件回执保留 `standard_stored_at` 和 `storage_time_uncertain`。这些字段提供延迟起点，真实 API 首次可见时间仍须由验收探针逐条测量，不能用提交耗时替代。

### 恢复步骤

1. 重新核对 184 的版本、任务、服务和配置。2026-10-23 22:53 的只读基线仍为实时 8,967 批 / 5,361,894 条，回填 1,161 批 / 2,896,007 条；发现与 DHCP 消费者均停用。
2. 相关回放、幂等和故障恢复验证通过后，按现场流程发布，迁移传 `--skip-backup`，保留 previous。真实数据库回放使用隔离数据库和独立主键，现场不造数压测。
3. 使用 consume-only / 1 观察 30 分钟，再以 2 路观察 30 分钟。恢复 passive 与独立 DHCP 服务后观察 2 小时。沿用原网卡、CIDR、协议和 DHCP-only 配置。
4. `discovery-recovery --recovery-id ID --cutoff RFC3339 --limit 500` 默认只读预览；增加 `--apply` 每次最多移动 500 批。它把切点前、未被租用的实时任务移入 backfill，保存原 lane、时间、偏移和错误；可重复分批执行，总积压不会因此减少。相同恢复 ID 不允许更换切点。
5. `scripts/benchmark/discovery-recovery-observe.py --base-url URL --phase consume-one|consume-two|passive --output FILE` 仅查询并保存 JSONL，不启动或停止服务。认证从 `PROXY_SENTINEL_BENCHMARK_TOKEN` 读取，不能把令牌写进参数或报告。默认观察时长为 30 / 30 / 120 分钟；`--smoke` 短运行不算验收。
6. 观察脚本检查消费者代次变化、心跳、分段停滞、连续两个 5 分钟超时率 >1%、以及四个 15 分钟窗口的净消化。完全追平后必须仍有成功消费且保持零积压。任何一致性错误立即停止扩量，保留现场证据后决定恢复上一运行模式或回退应用。

`config/service-expectations.json` 可声明两个发现 systemd unit 的预期状态（running / stopped）。完整安装和应用升级均只读核对；不匹配阻止发布继续，未声明会明确显示 unspecified，不根据 enabled 状态推定应该启动。恢复时必须记录完整预期状态，主动停用的服务不会因检查被启动。

### 存储成本与保留

- 消费运行状态每个配置的消费者/lane 一行，每 5 秒覆盖；汇总每 lane 一行，后台扫描待处理任务生成。请求不聚合大队列。阶段名为固定集合，不用事件 ID 做指标标签。
- 租约及进度增加每段领取/提交的小型更新，保留现有待处理索引和原输入。恢复清单每个移动批次一行，为受控操作的审计依据；不自动删除未完成或待验收的恢复清单。
- 标准事件回执每事件修订一行，主键支持重试核验；新增已确认回执的时间索引供每小时最多 1,000 行清理。满一年且已有相同内容的持久投影回执、无案件保护才允许移除冗余写入回执；未确认写入不自动过期。投影幂等依据与受保护证据继续保留。
- 案件证据增加身份索引，避免清理时扫描全部案件；写成本仅在案件固化证据时增加。容量测试必须计入这些索引、后台汇总与长期回执增长。
