# 镜像访问端口批量查询成本审查（2026-11-02）

## 当前结论

`/api/v1/discovery/observed-ports` 的 20 目标读取会在控制面 500 毫秒限时内偶发失败。r39 页面已将弱端口线索移至详情，正常列表不再发起批量读取；接口仍接受最多 50 个目标，其他调用者仍可能触发慢查询。本审查只读现场真实表和现有查询记录，没有部署或生成现场测试数据。

在当前表上显式把现有条件从 `WHERE` 移至 `PREWHERE` 没有减少逻辑读取量，因此本轮不改查询代码或超时。单目标成功样本不能代替 20 至 50 目标的延迟验收。

## 只读证据与语义边界

- 表 `discovery_observed_flow_ports_10m` 为 `AggregatingMergeTree`，按天分区，排序键 `(sensor_id,src_ip,window_start,proto,dst_port)`，10 分钟桶保留 7 天。`last_seen`、`evidence_id` 是聚合状态；三条既有物化视图分别写入旧 flow、初始 SYN 和匹配 SYN-ACK。查询在两小时范围内合并每个端口的状态，优先显示匹配 SYN-ACK 的时间与证据，最后按每个传感器/IP 的时间选前 8 个端口。缩短窗口、提前限定 8 个原始桶行或忽略 SYN-ACK 都会改变结果语义。
- 184 当次活动表约 218 万行、约 100 MB 磁盘字节、11 个活动 part，marks 文件合计约 7.9 KB。这是增长中的瞬时值，不是七天稳态容量。对一条真实 20 目标请求，`EXPLAIN indexes=1` 在时间过滤后保留 6 个 part、125 个 granule，主键再缩到 38 个 granule、19 个范围；最终结果仅 85 行。按约 8,192 行的默认稀疏粒度，读取大量相邻目标的数据是主要成本候选。
- 从现场 query log 取该请求的 SQL，在同一固定历史窗口做两次只读诊断。原查询：85 行、SHA256 `0880d8b2393345f898cb3eefe34cfad3149a3c67d7e37dd897ca3f4aa69d0258`，读取 212,922 行/51.3 MB、114 毫秒。显式 `PREWHERE`：85 行、同一 SHA256，读取 286,650 行/55.0 MB、3,283 毫秒。两次执行的缓存和 part 状态不同，时间不能直接归因于 `PREWHERE`；两者均读取数十 MB，缺乏过滤前推可显著改善的证据。先前 r38 的冷读约 1.7–3.3 秒并出现接口 500，符合余量不足，仍不是持续分位统计。
- 当前控制面保留 500 毫秒有界超时并显式返回读取错误。调大超时只会隐藏慢读和占用资源，不能解决多目标随机读。

ClickHouse 对 [稀疏主键、granule 与不可变 part 的说明](https://clickhouse.com/resources/engineering/what-is-columnar-storage)支持上述读放大机制判断；具体收益仍以本项目的数据分布和实验结果为准。

## 可验证的下一阶段方案

优先在**同一读模型的数据结构**上试验较细的主键 granule（例如 1,024 行），维持现有排序键、三种来源、聚合状态和七天 TTL。它可能降低随机目标引起的整块伴读，但尚未用相同真实数据和冷缓存验证；压缩块、part 数量、磁盘等待仍可能主导耗时。仅加 `src_ip` 跳过索引的收益也不明确，因为现有主键已经把 125 个 granule 缩至 38 个，且跳过索引仍不能只读取 granule 内匹配的行。

不能改写已应用的 ClickHouse 059–061 迁移。若本地受限实验显示读写收益，可通过新迁移建立同结构、较细粒度的候选表及对应三个物化视图，保留旧表和旧视图；从固定新输入时点双写，至少等待完整两小时查询窗口，再对相同目标、时间范围和证据 ID 影子比较。确认读结果、冷/热耗时、写入延迟、part/merge、磁盘与回退后，才把读切向新表。回退期继续双写，旧表与应用回退入口保留；过渡结束且覆盖范围、唯一证据和案件引用核验后，另经授权退役旧表。这样的短期双份紧凑聚合只为兼容切换，须限定期限，不能变成永久副本。

这一路径在双写期使该聚合表的物化写入和磁盘占用近似增加一份，细粒度索引还会增加 mark 数量与合并成本；实际增加量必须在独立测试和现场受限阶段测量。当前约 100 MB/218 万行只能作为短时基线，不能线性外推为七天承诺。若较细粒度仍无法满足冷读，应考虑把该热表移至独立快盘或建设按传感器/IP 的精确有界读模型，并分别评估新增写放大、保留和失效机制。

## 验收门槛

- 独立测试库用同分布数据比较原表/候选表的结果、`EXPLAIN`、冷/热读取行数与字节数、P95/P99、持续写入和合并成本；无需在 184 造数。
- 现场先限量真实输入双写并核对同一两小时窗口的目标集合、证据 ID、SYN-ACK 优先级及晚到事件；查询失败、无记录和处理中保持可区分。
- 只有实测数据证明收益后才切读；保留旧表、原文、迁移账本和应用回退，单独授权发布及后续退役。
