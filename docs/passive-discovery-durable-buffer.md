# 被动发现持久积压缓冲兼容阶段

## 作用和边界

当前发现 worker 将每个已写入 journal 的段同步送入 64 槽投影队列。投影持续慢于自然输入时，队列回压采集写入，随后 256 批收包队列也会满，采集停止。此候选允许投影落后期间继续把**有界数量**的新段写入现有权威 journal；三个 lane 只在内存中持有段 ID，原文、源游标、ACK 和最终确认仍由原 journal 保存和恢复。不增加第二份原文，不跳过投影、归档或检索，也不改变投影的单工位顺序。

缓冲只能延后持续净积压导致的停采。自然输入长期大于投影能力时，仍会到达上限并产生可见停采缺口。容量结论必须分别测量输入、journal 接收、三个 lane 的确认、未释放段、资源和页面可见延迟。

## 开关与容量

候选默认关闭，沿用原来的 64 槽队列和处理次序。单独的兼容发布先保持关闭，确认读取和回退后再在下一版通过以下三个环境变量同时开启；不能只设置其中一项：

| 变量 | 含义 |
| --- | --- |
| `PROXY_SENTINEL_PASSIVE_DURABLE_BUFFER_SEGMENTS` | 最多容纳的未释放段数，范围 517–16,384 |
| `PROXY_SENTINEL_PASSIVE_DURABLE_BUFFER_BYTES` | 未释放段正文的保守预算；每段按最大 4 MiB 计，不用小段均值冒险 |
| `PROXY_SENTINEL_PASSIVE_DURABLE_MIN_FREE_BYTES` | journal 所在文件系统必须保留的可用空间，至少 1 GiB |

实际硬上限为段数配置与 `字节预算 / 4 MiB` 的较小值。软上限比硬上限少 258 段，预留收包队列的 256 批、当前写入和最后一批。每次 journal 成功提交后检查剩余空间；在低于 `最小可用空间 + 258 × 4 MiB` 或达到软上限时，停止抓包，让已有内存批次写完并使进程以明确错误退出。`Restart=on-failure` 重启后先恢复 journal 段，待未释放量降到软上限的一半且磁盘空间充足，再重新打开抓包。若现存未释放段超过新配置的硬上限，启动明确拒绝缓冲模式；须恢复原限额或以受控 `stream-drain` 消退旧积压。不会删除、跳过或把这些段记为完成。

周期 `passive stream metrics` 新增 `durable_backlog`，给出未释放段、保守字节、两个限额、磁盘可用空间及其检查时间、恢复段数和暂停原因；暂停和等待还写入独立日志。捕获统计的 `updated_at` 在停采期间不会前进，应据此审计覆盖缺口。若文件系统可用空间查询失败，也停止采集并等待复核。其他进程可能同时消耗磁盘，因此阈值不是磁盘不满的保证；追加失败会保留明确错误，不把内存批次记为已持久化。

## 兼容、验证与现场阶段

- journal 文件、源游标、ACK 与段格式不变；旧段及新段仍按首次接受时间顺序恢复，投影继续单工位处理。所有 lane ACK 和最终确认成功后才释放段及配额。程序中断后从 journal 重新计数，未排队的持久段重新入队。
- 首版只发布默认关闭的兼容代码和测试，确认旧流量无回归；开启模式后，`previous` 必须是能快速重载该积压的兼容版本。r65 虽可读取同格式 journal，但其 64 槽启动队列会随大量积压长时间阻塞抓包，不能把它视为等效的快速恢复入口。
- 单元及回放覆盖：上限与 256 批排空余量、外部停止与容量暂停原因区分、磁盘空间不可核验、重复段计数、真实 journal 的 70 段有序恢复与无投影消费者入队。上线前还需受限真实流量观察容量、磁盘增长、重启恢复时间、停止和恢复的可见时间、ACK/最终确认、查询延迟；本地磁盘空间不足时不启动完整 184 快照，184 不造数压测。
- 此版本不解决 PostgreSQL 每事件键写入造成的持续吞吐缺口。达到上限后服务可能仍 `active`、后台仍消费旧段，但实时镜像覆盖已暂停；必须以采集统计和 journal 进度判断，而不能只看 `/readyz`。
