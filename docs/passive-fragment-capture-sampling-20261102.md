# 被动发现分片抓包短采样（2026-11-02）

184 测试环境 `bond0` 上的发现进程启用 DNS-SD、SSDP、ARP、LLDP，`--allow-cidrs` 与采集配置均为 `10.202.0.0/16`。此前约 26 分钟的 `capture.stats` 累计 `other.received=54,456,444`、`fragment_drops=60,270,393`；前者不是有效发现事件数，后者包含重组槽满、超时、重叠或无效片段。

[`CaptureFilterFor`](../internal/discovery/capture_filter.go) 在有启用 UDP 协议时，按端口检查 IPv4 首片，却允许任意 IPv4 UDP 后续片进入用户态；[`FrameDecoder`](../internal/discovery/frame_decoder.go) 会尝试在最多 256 个重组组中处理这些片。因此本次样本支持“无关分片大量进入解码路径”的判断，但短采样不能代表全天流量，也不能把 `fragment_drops` 等同于丢失的发现报文。

当前输出范围由解析后的设备地址决定，不能仅按外层 IP 源或目的地址过滤：范围外发送者的 DNS-SD 应答仍可能声明范围内地址。经典 BPF 无法无状态地从后续片获知首片 UDP 端口。仅保留源或目的在 `10.202/16`、或目的为发现多播的后续片，在本次补采样本中会保留 1/2,000，但可能漏掉双端范围外、载荷声明范围内地址的分片应答；暂不修改 BPF。下一步若要试该边界，应先做显式可回退开关与分片回放，再用真实输入比较有效 DNS-SD/SSDP 事件、重组完成率、CPU 和捕获积压，不把短样本视为现场验收。
