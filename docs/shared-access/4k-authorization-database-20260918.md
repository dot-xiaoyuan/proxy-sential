# 4K 数据库授权自动读取

## 管理端配置

入口：系统管理 → 旁路处置网关 → 连接器与安全门槛 → 对应连接器的「4K 数据库授权」。按连接器保存独立的数据库地址、端口、数据库名、用户名、密码、TLS 和可选授权记录 ID，支持多个认证系统配置隔离。

「保存」只校验配置并加密落库，不等待外部数据库连接。「保存并检查授权」先保存，持久化检查任务并返回202，再由后台执行只读查询，展示授权 ID、App ID、接入组织和到期时间。此检查不验证管理接口或在线清单，也不下线用户。

数据库密码使用现有 action-master-key/AES-GCM 加密后保存在 PostgreSQL；GET、PUT 响应不回显密码，编辑留空保留原值。appSecret 只在后端短暂用于申请原生管理接口令牌，不持久化到 Sentinel，不返回浏览器，不写入日志。

## 选择规则及运行集成

MySQL 在 read-only 事务中查询固定的 authorization 表，仅接受 status=0 且 expired_at=0 或未到期的记录，到期判断使用数据库当前时间。指定 ID 使用参数查询；未指定时要求恰好一条有效授权，多条时明确要求指定 ID，不随意取第一条。账号登录密码不参与管理 API 鉴权。

既有原生连接器运行时优先使用该连接器在管理端保存的数据库配置。每次申请令牌前重新读取 authorization，无凭据缓存；配置存储失败、数据库读取失败、记录过期、禁用或歧义都停止调用，不回退到静态凭据。

新原生私有运行配置使用 `credential_source: 4k_database`，无需 app_id/app_secret；完整示例见 examples/shared-access/native-actions.json.example。数据库配置尚未填写时该模式明确失败，不使用占位凭据。既有未配置数据库且仍声明静态凭据的隔离安装保留兼容。

该功能解决管理凭据来源。原生 API 地址、证书校验、权威在线清单、接入范围和人工处置准入继续沿用独立配置，数据库查询不替代在线清单，也不绕过影子、账号限定、撤销或会话复核。本轮没有读取 190 的在线 Redis，没有 SSH 190，没有自动操作门户或发出真实下线。

## 接口与迁移

- GET /api/v1/actions/connectors/{id}/4k-database：无密码配置。
- PUT 同地址：保存配置；首次必须填写密码，后续留空保持。
- POST 同地址：持久化异步只读检查，返回202任务；GET /api/v1/tasks/{id}获取检查结果，无 appSecret。
- 三种方法都要求 integrations:write，普通只读用户不能查看或修改数据库配置。
- 版本化 PostgreSQL 迁移 044_4k_authorization_database.sql，新表与旧运营全量保存分离，数据库密码更新使用相关连接器事务锁。
