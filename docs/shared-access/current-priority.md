# 开发阶段收缩计划（2026-09-16）

本计划替代原先完整历史保留、七天回填和全面业务补齐的推进范围。开发历史无需回填；资源集中用于磁盘稳定和当前功能验证。

## 目标及顺序

### 1. 停止历史负担

核实服务及任务状态；停止七天回填、历史重分类和周期补扫，禁止自动再次创建，保留实时处理。验证重启后历史任务不恢复、实时游标仍推进。不再为旧开发数据做迁移、恢复和完整性补齐。

### 2. 实际释放空间并限制增长

先记录磁盘及各目录占用。清理本项目可重建的开发历史快照、分类结果、影子运行副本和开发备份，只保留必要的小型正反回放及验收记录。删除或重建前确认对象归属、依赖，保护代码、配置、凭据、必要证据和审计，不清理其他项目或归属不明对象。选择实际释放磁盘的方式，不为保留无用历史进行昂贵整表整理。

落实快照及影子文件的有界保留和日志轮转，修复重复保存累计原始流量等增长来源。验证实时采集、策略及案件查询。

验收：磁盘使用率目标低于 80%；安全可回收对象不足时，报告明确剩余占用，不越界删除。至少观察一小时，报告实际可用空间、写入量及增长变化。删除行数不代表空间释放。

### 3. 最小人工处置闭环

复用已有共享正例及正常单设备反例，仅补关键缺失测试，不重复大规模压测。使用 192.168.0.190 认证环境和已指定测试账号，打通 Sentinel 的“共享证据 → 事件时账号 → 人工确认 → 全部当前会话下线 → 重新认证恢复”。身份冲突、过期、证据不足时禁止执行；发送前复核证据及会话，覆盖重复确认、身份变化、多会话和部分失败。

保留影子准入、审计、冷却、发送前撤销和紧急停止。一次性下线不能撤回原连接，恢复验证为重新认证。只操作指定测试账号，不开放自动处罚。

验收：通过 Sentinel 页面或现有 API 完成完整链路，保存记录；此前直接调用认证 API 的成功不能替代本项。合成流量结果不宣称真实校园网准确率。
