# 双栈认证身份补齐（2026-09-15）

原完整清单转换仅取 ip/ipv6 中第一个非空字段，双栈会话会丢失 IPv6 归属。新增回放先复现该失败，再改为输出全部有效地址。

## 实现与约束

- 同一来源会话的 IPv4、IPv6 使用相同 session_id、source_session_id、source_instance_id 和稳定 endpoint_id。
- IPv4 映射 IPv6 规范化后去重，避免重复记录。空地址及未指定地址占位不生成身份；没有任何有效地址仍拒绝整批。
- 非空地址非法、带 zone 或为组播地址时拒绝整批，不静默丢弃第二地址后提交不完整清单。
- 展开地址后最多 10,000 条，超过接收接口上限时拒绝，不部分发送。
- 完整清单 expected_count 和回执校验按实际地址记录数；采集日志保留原 sessions 字段表示源会话数量，新增 address_records 区分地址记录数量。

## 验证

- 单元回放：双栈、IPv6-only、映射地址去重、未指定地址占位、第二地址非法、组播拒绝通过。
- 真实本地 PostgreSQL 回放：两个地址持久化并关联同一账号，稳定终端只计一台；后续完整清单移除 IPv6 时，仅结束 IPv6，IPv4 仍在线，历史 IPv6 归属仍可查询。
- legacy4k 与采集程序竞态测试通过，包含之前修复的跨轮失败重试用例。
- 新候选程序在 190 执行只读 preview：81 个来源会话、161 条地址记录、80 条种子会话。此结果证明旧实现确实少导出了地址，但这些 IPv6 主要来自种子数据，不能算真实校园双栈准确率验收。

证据位于 `artifacts/shared-access-dualstack/`。本轮只更新 190 的 lab 候选二进制并执行预览，未替换默认程序、未安装常驻服务、未部署生产。

## 控制器接入调查

190 原生 `/api/v2/base/online-drop` 继承 v1 实现，要求 user_name、rad_online_id、drop_type。服务端先检查该会话 ID 是否属于指定账号，再执行下线。`/api/v2/base/online-data` 分页返回部分在线字段；后续核对发现其 `searchParams` 是输出字段选择，不是账号过滤，且没有原始在线 ID，不能用于精确处置核验。按账号查询应进一步核对 `/api/v2/base/online-equipment` 的字段配置与分页完整性。

后续连接器必须使用原始来源会话 ID，不能把 Sentinel 的复合 session_id 原样传给原生接口；不能退化为按共享 IP 操作。仍需核验下线类型与后台执行结果、API 管理鉴权、限速及解除能力，当前未据此执行处罚。
