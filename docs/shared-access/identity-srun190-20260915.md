## 完整性与重试

现场禁用 EVAL，因此采集采用有上限的预读成员列表，再在 MULTI/EXEC 内同时读取成员列表、所有相关哈希、Redis 实例标识和观察时间。前后成员不一致、超出数量上限、缺失哈希、身份不一致、重复或非法记录都会拒绝整批；禁止把不完整清单提交为离线依据。真实 Redis 6.2 及现场只读预览均已通过。

新工具 `cmd/srun-identity-snapshot`：

- 独立进程，默认每 60 秒对账；每次最多 1000 条，最大允许配置 10000 条，防止无限事务。
- 会话身份包含 Redis run_id，保存原始会话 ID，避免实例重启后复用会话身份。
- 发送前将原始待提交清单原子写入本地 0600 文件；持久化失败退出，不发送无法恢复的数据。
- 服务端确认批次身份、完成状态和记录数后才清除待提交清单。响应失败保留原清单及幂等身份，重启继续提交。
- 超过服务端七天可接受范围的待提交清单会持续报告失败，需管理员核验后处理；不自动丢弃旧状态并冒充成功。
- `--preview` 仅输出校验结果、时间、记录数和种子数据数量，不发送或输出账号/IP。

现场已安装 `/opt/proxy-sentinel-bridge/srun-identity-snapshot`，Redis 密码由原有配置读取到本机权限为 0600 的文件。未安装常驻服务，未改变原认证系统配置或业务数据。

```sh
/opt/proxy-sentinel-bridge/srun-identity-snapshot \
  --redis-password-file /opt/proxy-sentinel-bridge/redis.password \
  --preview
```
