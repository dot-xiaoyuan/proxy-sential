## 设备快照保留

`cmd/device-retention` 默认只读，固定保留至少七天。通过 `PROXY_SENTINEL_POSTGRES_DSN` 提供连接；不将凭据放入命令参数。示例：

```sh
go run ./cmd/device-retention > retention-preview.jsonl
go run ./cmd/device-retention --apply --batch-size 500 --max-batches 1 > retention-result.jsonl
```

每次执行先输出日期分布、可删除行数、表及索引/TOAST 总大小和保护说明。执行模式每批最多 1000 行，默认 500 行、一次一批；批间间隔一秒，支持 SIGINT/SIGTERM。可由外部维护调度按需重复运行，不接入采集热路径。

保护规则：

- 所有案件当前 IP 及历史证据 IP 的全部设备历史保留。旧案件没有可靠的设备快照外键，不能只凭时间猜测哪些历史已无用。
- 任何案件或历史证据缺少 IP，暂时保护全部快照，直至关联情况确认。
- 各传感器/窗口最新批次、各 IP 最新快照保留，包括已超过七天但没有新观测的 IP。
- 不修改案件证据、风险证据和审计记录。

执行前逐批重新检查保护条件。新增迁移 024 在案件和历史证据写入时登记事务级 IP 保护锁；清理使用相同的非阻塞 IP 锁，缺失/非法引用使用全局保护。不再锁住整张案件表，未安装或禁用保护触发器时拒绝清理。候选筛选在保护锁之外执行；删除语句上限仍为 5 秒。锁忙有限重试，语句超时逐步缩小批量，其余错误退出；已提交批次保留，允许重新执行。使用 SKIP LOCKED；某轮返回零只表示当时无可锁定候选，后续维护仍可重试。

日期行数用于观察写入分布，不冒充日磁盘净增长；表总大小需按日采样比较。DELETE 产生的是可回收/复用空间，不承诺磁盘立即变小。当前保护策略有意保守：案件关联 IP 的历史仍可能增长，待建立可靠的精确引用关系后才能收窄保护范围；本轮不宣称全表大小已恒定。本工具不执行 VACUUM FULL、表重写或备份删除。发布包包含 `bin/device-retention`，现场使用该二进制与现有环境变量，不需要安装 Go。

## 应用扫描

数据库任务使用固定总范围以及独立时间片：默认 600 秒。ClickHouse 聚合键和取明细均加时间范围，维持 256MiB 查询上限。

- Job JSON 新增 `scan_from`、`scan_to`、`scan_seconds`，无需改表；OpenAPI 与生成的前端类型同步。
- 每片内部仍按时间、传感器、事件 ID 排序分页，每批 1000 条。
- 空片只推进片边界；恰好满页时继续原片，避免同一时间点跨页丢记录。
- 批次唯一身份包含事件游标及片边界，连续空片不会冲突。
- 已准备批次仍先恢复原结果再提交进度，不重建旧批次。
- 内存/超时错误持久化缩小范围，逐次减半至 1 秒；不推进已确认事件游标、不丢弃控制请求。其他错误不盲目缩片。
- 一秒仍失败则保留位置、累计失败信息，不跳过事件。

既有任务从原事件游标继续，已提交重分类修订不变。实时优先、租约、暂停/取消和幂等写入沿用已有流程。

## 按物理存储量分批与引用并发保护

现场只读统计发现旧快照平均约 293376 字节，最大约 81 MB。新增双重批量限制：最多配置行数，且普通批次 inventory 存储量不超过 8 MiB；第一个超大快照单独处理，不跳过。其超时沿用同一单条重试，不再错误地下调后续普通批次的行数预算。超过有限重试次数仍失败则停止并报告，成功提交之前不声称删除完成。

预览新增每个 UTC 日期的 `inventory_bytes` 和 `max_inventory_bytes`，表示现存快照 JSONB 的存储字节量；不是整表磁盘占用、日净增长或已释放空间。日写入快照数仍来自日期行数。持续采样 `relation_bytes` 和文件系统剩余空间才可计算实际增长。

迁移 `024_device_retention_reference_guard.sql` 通过数据库触发器覆盖所有案件及证据写入路径。正常 IP 只与同 IP 清理互斥，不相关 IP 的案件仍可写入。未知引用保守地与全部清理互斥。清理尝试锁失败后释放本批全部锁并重试，不等待多 IP 锁形成死锁。迁移 DDL 的锁等待上限为 2 秒，不在业务繁忙时无限等待。

真实 PostgreSQL 回归增加：并发未提交案件保护、历史证据新引用保护、未知引用保护、不同 IP 写入不被阻塞、缺失触发器拒绝删除、两个大快照跨批处理。相关包竞态测试全部通过，日志见 `guard-final-tests.txt` 和 `retention-retry-tests.txt`。当前前端仅生成类型保持同步，布局未变，生产构建再次通过。

## 周期维护配置

`deploy/systemd/proxy-sentinel-device-retention.service` / `.timer` 提供独立周期任务，默认每小时运行，随机延后不超过五分钟，每轮最多 120 批，十五分钟超时发送 SIGTERM；已提交批次保留，下轮重新预览后继续。systemd 不会并发启动同一个 oneshot 服务。默认路径 `/opt/proxy-sentinel`，自定义部署目录需同步替换。

配置从既有受保护的 `runtime.env` 读取数据库连接，批量参数可在 `config/device-retention.env` 显式覆盖。日志为逐批 JSON，可用 journalctl 检查提交与失败；停止 timer 可暂停后续维护，停止 service 可中断当前执行。日志不输出快照明细。进程低调度优先级不等于数据库资源限额，数据库工作量仍由批次字节上限、短事务和批间间隔控制。

周期任务需在迁移 024、清理预览和有限批次验收通过后启用；配置文件存在不代表现场 timer 已启用。当前是否启用以现场 systemctl 验证记录为准。
