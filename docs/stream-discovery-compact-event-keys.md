# 流式发现紧凑事件键：兼容阶段与切换门槛

## 依据与目标

184 的 r34 在 2026-11-01 17:54–18:34 连续观察中，四轮被动采集都达到 256/256 满队列，发生三次自动重启；续采确认第四次重启。投影队列长期为 64/64，`projection.write` 常为数秒一段。只读 PostgreSQL 快照显示旧全局事件键台账约 2,003 万行、总量 9,466 MB，其中主键索引约 4,636 MB。旧表主键包含三个文本字段，新事件的逐条唯一索引写入是明确的成本；这组快照不能证明它是唯一瓶颈，也不能预测新索引的现场收益。

本方案保留逐事件去重、跨月重放、原月份回执定位和冲突拒绝语义，用固定 32 字节摘要缩小新键的主索引。完整的代次、作用域、事件键、内容哈希、首次接收时间和回执月份仍在表行中；摘要冲突必须核对完整键，不能当成同一事件。

## r35 兼容阶段

- PostgreSQL 迁移 214 新建 `stream_discovery_event_keys_compact`、摘要函数和按首次接收时间的 BRIN 索引；旧台账、回执及原始证据不改写。案件证据触发器与 Go 读取均接受任一台账，但双写记录若哈希或月份不一致则拒绝引用。
- 被动采集继续生成原来的 `stream-` 事件号。命令行认识 `--passive-compact-event-keys`，但此版本明确忽略它，避免应用从后继版本回退时因旧参数无法启动或继续产生新格式。
- 本版本能够读取、投影、确认 `stream2-` 段；投影新键时在同一 PostgreSQL 事务写紧凑和旧台账。回执查询先查紧凑台账，仅在完整身份不存在时有界回查旧台账，以兼容其他来源曾使用相同前缀的键。
- r35 本身不产生新格式，也不减少正常被动流量的旧索引写入，不能据此宣称吞吐改善。r35 回退到 r34 时，正常生产路径仍只有旧格式。

## 后继切换与回退

只有在 r35 的真实迁移、读取及回退兼容已验收，且 `previous` 明确为 r35 时，后继版本才可单独启用 `stream2-` 生产和紧凑台账单写。后继版本必须把生产开关同时传给投影写入选择；关闭开关时仍能处理已有 `stream2-` 段。运行中新键落入紧凑台账后，应用只能回退到能处理该台账的 r35，不能回退到 r34。r35 对回退期间未投影的 `stream2-` 段双写两账本；已投影的段按已有投影标记和紧凑台账继续确认，不能重复改写事实。

切换前还需验证旧台账中有无相同作用域的 `stream2-` 键，排除来源前缀冲突；后继版本需约束非被动来源的新事件不能占用该保留前缀。切换与关闭均不能重置来源游标、确认标记或未处理段。

## 存储成本与生命周期

新主键索引的读取收益是按摘要快速定位全局事件键和原始回执月份；写入仍为每个新事件一条 PostgreSQL 行、一次唯一索引维护以及摘要计算。BRIN 仅为按首次接收时间扫描提供低写入成本的准备，不会自动清理。结果失效由不可变事件键和同事务回执状态决定，不使用缓存。旧表与新表目前都没有完成“热查 30 天、归档至首次入库后一年”的核验归档及安全清理闭环；`stream_discovery_receipts` 也没有未来月份分区维护，会在已预建月份之外进入 default 分区。不能因新索引存在而缩短保留期或直接删除去重键。

逐事件键拦截同一事件换段重放；`stream_projection_segments` 仅按段 ID 去重，不能替代它。安全退役需要先核验原文、回执和变更历史归档的覆盖范围与哈希，再建立可持久核验的来源位置水位或完成代次受控关闭、清空待办，之后才能有界清理对应键。`archive_state=confirmed` 只说明三条处理 lane 已确认，不能当作归档覆盖核验。案件引用原文继续独立保护；没有上述证明时新旧键都必须保留，容量测试应包含持续增长和后续清理成本。

新增索引和结果表的增长测试仍待完成：记录实际输入速率、每万条表/主键/BRIN 的增长、WAL 量、投影段耗时、CPU/IO 与查询延迟，并在受限真实流量下连续观察满队列、重启和未确认段。现场不造数压测；本地数据库栈已停用。若增长、生命周期或持续吞吐未达到约定，则保留旧生产格式和回退入口，不宣称容量达标。

## 当前验证边界

兼容代码已有针对键身份、摘要碰撞、双写、已提交键不重放、归档确认、跨来源前缀回查和混合格式拒绝的 Go 回放。`go test ./...`、相关包 race、`go build ./...`、`go vet ./...` 与 Linux amd64 构建已通过。真实迁移和案件触发器的集成用例只允许在独立远程 PostgreSQL 测试库运行；当前未配置该库，所以本轮跳过，不能算作 SQL 验收。后继版本自身的现场回退、索引增长测试以及 184 持续容量验收均未完成。r35 发布与后继切换须分别取得对应版本的现场更新授权。
