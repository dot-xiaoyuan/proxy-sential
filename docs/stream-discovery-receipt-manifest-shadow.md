# 被动发现段级回执清单影子阶段

r56 为后续减少 PostgreSQL 逐事件回执行准备可核对的数据。此阶段仍写入现有每事件 `stream_discovery_receipts`，所有读取、案件保护和归档确认仍以它为准。`PROXY_SENTINEL_PASSIVE_RECEIPT_MANIFEST_SHADOW` 默认关闭，只在完整迁移与回退版本核对后受控开启。

## 存储与语义

- 每个首次入库的被动 `stream2` 事件继续占用一条紧凑键台账。影子开启时，该行同时记录所属 `segment_id` 与从零开始的投影事件序号；无耐久来源位置的段与重放键不补写定位。序号按 `prepareStreamDiscovery` 的结果排列，不按原始段中非投影事件计数。
- 每段新增一条 `stream_discovery_segment_receipt_manifests`，只存归档月份、正文布局及按投影事件序号排列的结果数组。重放旧键的位置为 `null`，不会冒充该段的新结果。段的 epoch、内容哈希、处理时间、事件数和来源位置继续以 `stream_projection_segments` 为准，不在清单重复存放。
- 段标记、首次键定位、事实、现有逐事件回执和清单在同一 PostgreSQL 事务中提交；任一写入失败时整段回滚。现有段级归档确认方式不变。r56 的 `archive_receipt_mode` 仍为 `event` 或 `segment`，后继版本省去回执行前须另设持久模式并完成兼容读取。

## 成本、保留与切换

清单新增一条每段的堆行和主键项，结果数组最多 1,000 项；紧凑键台账增加两个可空列，但不增加每事件索引。影子开启会增加写入量，目的在于用真实输入核对未来读取所需的数据，不构成吞吐优化。清单没有缓存失效问题，提交后内容不可变。它与紧凑键、段标记、唯一原文和案件引用一起受热查 30 天、归档至首次入库后一年及归档核验约束保护；本阶段不实施删除或退役。

r56 可关闭影子开关并回退到继续读取旧回执的兼容应用；清单与定位列保持向前兼容。后继版本只有在单/批回执、设备历史、案件证据触发器、新鲜度和识别诊断均能读取并核对清单后，才可考虑停止写入逐事件回执。清单或段标记缺失、序号越界、结果数组长度与段事件数不符必须明确报缺口，不能伪装为确认或无记录。

本地单元与回放、全仓 Go 测试/构建/vet 已通过。暂无独立 PostgreSQL 测试库，真实迁移、表/索引增长及写入成本尚未集成验收；184 只能使用真实持续输入观察，不造数压测。现场开启影子后需按固定时间窗记录段数、清单字节、紧凑键增量、事务耗时、队列和磁盘，确认额外成本可接受再推进读取切换。
