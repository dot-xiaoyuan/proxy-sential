# T10 页面与识别基线

本基线用于验证页面一致性、UA 可信度和网络报表整改，禁止以浏览器持久缓存代替冷启动验收。

## 数据基线

每次发布前记录以下 24 小时和 7 天指标：终端总数，厂商、品牌、型号、类型、OS、生态线索覆盖率，标准事件 `endpoint_id` 归属率，域名生态匹配、归属、未归属及冲突数量。集成测试必须使用本次运行唯一的规则版本和业务主键，并通过 `t.Cleanup` 删除测试数据；历史固定版本 `domain-integration-v1` 仅视为测试残留，不得作为现场识别结果统计。

## 页面基线

业务列表统一检查风险处置、终端、事件、案件、复核兼容页、影子运行、审计、处置动作、采集诊断和系统管理列表。基线记录分页控件类型、默认页长、服务端总数、响应体积和 TTFB。

页面高度以禁用缓存后的首次进入为准，在 390×844、1280×800、1440×900 记录 `document.documentElement.scrollHeight`、视口高度、横向溢出元素、折行的 IP/MAC/UUID/Hash/域名/按钮。1280×800 的主要运营页面常用区域目标不超过 1.2 个视口，长证据必须进入详情标签或抽屉。

## T10 初始问题

- 原始 UA 去重数量被错误解释为设备数量和冲突置信度。
- 域名生态已匹配但无 endpoint 归属的事件没有运营可见性。
- 各列表同时存在页码、仅上一页/下一页、页长位于页头以及无分页等交互。
- 访问目标被命名为应用，TOP 数据以长列表或进度条堆叠，页面纵向过长。

验收数据必须区分“规则匹配”“终端归属”和“正式画像字段”，访问生态不得计入硬件品牌识别率。
