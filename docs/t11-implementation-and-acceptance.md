## 功能与操作

1. `/shadow-runs` 展示报告生成时间、`ready`、阻塞原因、每日等级复核覆盖率、误报原因和证据类型。`GET /api/v1/shadow/review-samples` 只读取现有每日导出，按日期、等级、游标分页，响应不含服务器路径。提交复核沿用 `POST /labels`；样本状态立即更新，汇总以定时评估生成时间为准。
2. `/devices/attribution` 按时间、Sensor、状态和原因下钻标准事件归属结果，展示事件、规则版本与身份解释。生态线索只表示域名生态，不充当硬件品牌。身份修正后的版本化回填可通过同窗口 `GET /api/v1/device-recognition/attribution-comparison` 与旧版本比较归属率、冲突量；只统计两个版本均有的事件 ID 和生态类型。比较前须完成身份修正并触发新版本特征库回填；两个版本必须都覆盖所选窗口。
3. 离线候选可通过 `proxy-sentinel risk batch --input evidence.json --candidate-policy candidate.json --output candidate-risk.json` 生成。候选配置包含版本，以及按证据类型的分数调整或按主体的负证据；不会写入在线规则。随后用 `proxy-sentinel evaluate rules --baseline baseline-risk.json --candidate candidate-risk.json --labels labels.jsonl --evidence evidence.json --baseline-version V1 --candidate-version V2 --strict --output comparison.json` 生成逐主体对比。报告列出证据、原始/最终分、置信度、窗口、解释和等级变化；有已复核回归、无已复核样本或无有效变化时严格模式失败。通过后仍需人工将候选纳入影子运行，不能据此启用处罚。
4. 新写入标准事件的 ID 在 Zeek、身份适配器跨批次保持稳定；Suricata 的稳定去重键忽略批次 offset。ClickHouse 保留原始事件及原证据 ID，新增按 Sensor/去重键归并的规范查询表。活动 TOP 与趋势使用可重跑的 10 分钟桶；查询只在所需日期和维度具备刷新数据时采用汇总，TOP 的首尾时间片由规范明细补齐。`proxy-sentinel refresh activity-rollup --days 2` 为定时任务，首次迁移刷新 7 天。恢复备份时重建规范查询表和汇总，回滚时停用新定时任务。

## 已完成的自动化验证

- 本地 `go test ./...`、前端 `tsc --noEmit`、生产构建、单元测试通过；原有 19 条和新增 7 条 Playwright 用例通过。新增页面在 390×844、1280×800、1440×900 捕获截图并用 DOM 探针检查溢出、按钮与标签不折行；截图对照了项目的中性底色、低对比边框、8px 卡片和移动端卡片化规范。
- 30 测试机的隔离 PostgreSQL 数据库通过身份会话边界、域名证据幂等、操作分页和风险重算测试。隔离 ClickHouse 数据库通过重复标准事件、汇总时间桶重跑、跨时间边界 TOP、归属诊断/版本对比，以及 10 万事件聚合测试；10 万事件测试含小于 1 秒的 TOP 查询门槛。
- 集成测试发现原有 ClickHouse 写入把 RFC3339 时间直接写成无时区文本，已修正新写入时的上海时区转换与微秒查询边界。历史事件保持原 ID 和数据，不作破坏性改写。正式切换前需针对历史窗口单独对账。

## 统一发布门槛与未完成现场验收

当前测试机报告 `ready=false`，0 条人工复核，无法满足高风险确认率 ≥95%、候选和正常真值样本量及每日等级分桶覆盖。尚未获得 30–50 台人工确认设备的真值清单，不能宣称发现率、误合并、重复创建、基础设施污染已验收。因此本次代码**不得直接切换测试机正式读路径或启用处罚**。

统一发布前按以下顺序执行：运营提供每日人工标签与设备真值；连续至少 7 天现场影子评估达到 `ready=true`，高风险确认率 ≥95%；在隔离库复演全部迁移、恢复和回滚；在真实库迁移后对同窗口明细、TOP、趋势及旧路径计数对账，重复导入同一批事件再对账，并实测 TOP TTFB ≤1 秒。30–50 台人工确认设备严格验证需输出发现率、误合并、重复创建和基础设施污染，归属率用同窗口修正前后版本对比。最后统一切换版本，保持自动降速、踢线、封禁关闭。
